# Theater 재작업

기준일: 2026-11-15. 앱 이름은 Theater를 유지한다. 현재 우리은행홀로 안내되는 블루스퀘어 뮤지컬홀의 공개 자료를 사용했다. 콘서트홀인 우리WON뱅킹홀 자료와 혼용하지 않는다.

- [무대기술자료, 2026-01-01](https://www.bluesquare.kr/pages/board/board.file.download.php?no=36&fld=attach1): 정원, 프로시니엄, 무대 및 피트 치수.

도면의 치수선은 화살표 앞에서 끊기므로 선분 길이만으로 축척을 잡으면 안 된다. 치수 보조선의 양 끝 기준 약 15.2 PDF point/m를 사용한다. PDF 회전은 270도이며, 추출 좌표는 회전 전 좌표다.

## 좌석과 높이

`scripts/generate-theater.py`는 PDF의 반복된 의자 방석 외곽(U자 또는 사각형)을 읽는다. 고정 일반석은 1층 958, 2층 430, 3층 270개, 회색으로 그린 OP석은 76개가 추출된다. 좌석 번호는 층별 공식 좌석도의 번호 범위를 별도로 대조했다. 예를 들어 1층의 33번 공백, 2층 뒤쪽 중앙의 짧은 열, 3층 3열 양옆과 마지막 열 중앙의 공백을 보존한다.

| 구성 | 1층 | 2층 | 3층 | 합계 |
|---|---:|---:|---:|---:|
| OPEN PIT | 990 | 430 | 270 | 1,690 |
| OP SEATING | 1,066 | 430 | 270 | 1,766 |

1층에는 휠체어 18곳과 모자동반석 14곳이 포함된다. 휠체어 공간에는 일반 의자를 그리지 않는다. 모자동반석은 뒤쪽 별도 유리실로 구분한다.

일반석 각 열의 높이는 종단면 의자 기준점을 읽어 공통 기준면으로 환산한 값이다. 1층 0~2.882m, 2층 6.324~9.624m, 3층 12.418~15.071m를 사용한다. 단일 종단면이므로 같은 열의 옆 좌석에는 같은 높이를 적용했다. 좌우 블록의 평면 각도와 각 좌석 위치는 PDF에서 추출했다. 예전의 고정 발코니 단차와 1층 이차식 경사는 사용하지 않는다.

앱 선택 방식은 **Floor / Row / Seat**다. 블록 이름은 표시하거나 요구하지 않는다. `block`이라는 내부 필드는 기존 착석 API와의 호환을 위해 1F/2F/3F 값을 저장할 뿐이다. 실제 열·좌석 번호를 새로 1부터 채우지 않는다.

공식 기술 평면에 번호가 없는 OP석에는 `OP 1`~`OP 3`과 열 안의 순서 번호를 붙였다. 이는 앱 식별자이며 공식 예매 좌석 번호라는 뜻이 아니다. 무번호 모자동반석의 열은 `FAMILY`로 표시한다. 이 두 예외를 일반석의 임의 24열 등으로 위장하지 않는다.

## 구조와 마감

- 프로시니엄 14.9×10m, 무대면 +0.93m, 피트 폭 15.6m·깊이 방향 3m를 반영한다.
- OPEN PIT에서는 바닥 메시 자체에 구멍이 있고 피트 바닥은 객석 기준 -1.87m다. OP 모드에서만 객석 기준 0m의 덮개를 설치한다.
- 각 열 바닥, 경사진 발코니 하부, 짙은 발코니 전면과 금속 가로 띠, 통로의 낮은 계단, 전면 조명 박스, 목재 벽 가로 이음, 반사 패널과 조명 브리지를 추가했다.
- 파란 패브릭 좌석은 전용 `bluesquare` 형상이다. 둥근 사각 등받이·방석, 짙은 목재 옆판, 팔걸이, 받침과 작은 좌석 번호판을 분리했다. 다른 공연장 좌석은 이 형상으로 바뀌지 않는다.
- 공식 사진의 회갈색 헤더 카펫을 기준으로 새 섬유 질감을 만들었다. 기존 붉은 체크 카펫을 재사용하지 않는다. 통로와 계단도 같은 카펫 마감이다.
- 사진을 기준으로 따뜻한 목재 색, 수평 슬랫, 짙은 조명실 개구부, 발코니 아래의 따뜻한 다운라이트를 맞췄다. 기존 음원·무대 스크린·음악 연동 조명 기능은 유지한다.

## 천장 단면과 사진 대조

운영사 내부 사진 3장과 기술도면 4쪽 종단면을 대조했다. 도면의 낮은 선은 천장 전체가 아니라 매달린 기술 통로의 하부다. 객석 위를 닫는 약 +22.137m의 높은 목재 주 천장과 그 아래 기술 통로의 마감면을 구분했다. 기존 검은 평면과 서로 떨어진 가로 보 대신, 주 천장·통로 하부·전면 개구부·경사 캐노피와 뒤쪽 연결면을 구성했다. 도면의 원점은 높이 PDF X=246.24, 깊이 PDF Y=558.84이며 15.2pt/m로 환산한다. 세 기술 통로의 하부는 각각 약 +15.197m, +15.797m, +16.839m다.

사진에서 확인되는 중앙·좌우로 나뉜 기술 개구부와 더 뒤쪽의 긴 개구부에는 깊이 있는 검은 내부, 막힌 뒷면, 조명 파이프·지주·안전망과 실제 무대 조명 기구를 넣었다. 밝은 목재 보만 떠 있고 뒤가 뚫려 보이는 형태로 두지 않는다. 매입등, 원형 환기 그릴, 절제된 패널 이음, 측벽 접합 마감과 상부 지지 부재도 추가했다. 천장·벽의 과도하게 큰 나뭇결과 채도를 줄였다. 객석등은 기존 house/show 상태와 함께 꺼진다. 무대 전면등도 마감면 위에 묻히지 않게 천장 아래로 옮겼다.

주 천장 및 기술 통로 하부의 주요 높이·깊이 구간은 도면에서 읽었다. 개구부 전면의 높이·깊이·가로 분할·정확한 폭, 앞쪽 캐노피와 뒤쪽 천장 연결 윤곽, 환기 그릴·매입등의 수량과 개별 간격은 공개 사진을 기준으로 추정한 것이다. 개구부는 관객 시선과 거의 평행한 경사면의 얇은 틈이 아니라, 사진처럼 내부가 보이는 세운 전면으로 만들었다. 객석 조명은 하향 배광으로 바꿔 천장에 생기던 큰 발광 얼룩을 줄였다. 실시간 렌더러에서 생략되는 간접광은 넓은 상향 면광원으로 근사해 하부 마감이 검게 죽지 않도록 했다. 반사 천장 평면도나 마감 상세도에 의한 실측 복원으로 표시하지 않는다.

## 발코니와 공개 출입구 연결 검수

독립된 앞판·좌석 단·평판 아래 마감 사이에 생기던 틈을 제거했다. 발코니는 전면, 앞쪽 낮은 통로, 좌석 단, 후면, 아래면과 양 끝 옆면이 같은 단면 정점을 공유하는 닫힌 메시다. 2·3층 각각 메시 경계의 모든 모서리가 삼각형 두 개에 속하는지 검사한다. 앞판 뒤쪽과 좌우 끝에서 바닥이 빠지는 회귀 검사도 포함한다. 단면에 따라 전면 통로는 첫 좌석 바닥보다 2층 0.064m, 3층 0.758m 낮게 놓았다. 3층 전면을 첫 좌석 높이로 일괄 올려 좌석을 가리던 배치를 사용하지 않는다.

공개 출입구는 총 12개(1층 6, 2층 4, 3층 2)다. 무대기술도면의 실제 문틀·회전축과 개구 선분을 다시 읽어 위치와 폭을 기록했다. 180도 개폐 궤적 전체를 문 폭으로 읽지 않는다. 전체 좌표와 원본 PDF 좌표는 `docs/references/theater-gates-audit.json`에 있다.

벽체와 표면 마감은 동일한 개구부 목록을 사용한다. 문 앞을 가로지르던 얇은 가로 줄눈과 돌출 반사 패널도 개구부 윤곽에서 잘라낸다. Walker의 몇 개 높이에서 쏘는 벽 검사만으로는 얇은 마감선을 놓칠 수 있으므로, 별도로 측면 문 개구부를 4mm 높이 간격으로 검사한다. 하단 인접 객석 단의 경사 구간에서는 벽 두께 안의 개구부를, 그 위에서는 돌출 마감까지 검사한다.

2·3층 발코니의 바깥쪽 약 0.9m 통로에는 출입구 폭 전체에 맞춘 수평 참을 넣었다. 닫힌 발코니의 경사진 옆면이 문 아래쪽 모서리를 메우던 문제를 없앤다. 좌석 아래 높이는 유지하며, 끝 단면의 참과 기존 객석 단 사이를 연결한다. 이 횡방향 참의 세부 윤곽은 통행을 위한 재구성이며 실측 높이로 간주하지 않는다. 참을 추가한 후에도 닫힌 발코니 메시의 모든 경계 모서리를 다시 검사한다.

| 층 | 게이트 | 앱 Z 좌표(m) | 개구 폭(m) |
|---|---|---:|---:|
| 1F | 측면 1 / 6 | 16.053 | 1.911 |
| 1F | 측면 2 / 5 | 30.543 | 1.903 |
| 1F | 후면 3 / 4 | 안쪽 34.945 / 바깥쪽 37.439 | 1.911 |
| 2F | 측면 1 / 4 | 28.688 | 1.903 |
| 2F | 후면 2 / 3 | 안쪽 34.834 / 바깥쪽 36.366 | 1.911 |
| 3F | 측면 1 / 2 | 28.976 | 1.911 |

Z는 앱 내부 기준 좌표이며 운영사의 건물 측량 좌표가 아니다. 후면 출입구는 안쪽 문과 바깥쪽 문 사이에 1층 약 2.495m, 2층 약 1.532m의 전실이 있다. 두 문과 전실 벽·천장·바닥을 따로 반영했다. 측벽은 평면의 약 0.30m 벽 두께를 포함한다.

**확인한 것:** 도면상의 출입구 평면 위치·개구 폭, 전실의 평면 깊이. 앱에서는 모든 공개 게이트에서 객석과 콘코스를 양방향으로 이동할 수 있고, 좌우 후면 계단으로 1↔2층 및 2↔3층을 이동할 수 있는지 검사했다. 단순 바닥 레이만 검사하지 않고 실제 Walker의 벽 미끄러짐, 서기 가능 여부, 단차와 머리 공간 판정을 같은 조건으로 사용한다.

**추정인 것:** 공개 도면에 치수가 없는 문 높이 2.3m, 측면 출입구의 횡방향 문턱 높이, 도면 밖 콘코스의 폭·전체 윤곽, 뒤쪽 층간 연결 계단의 배치. 계단은 통로를 가로막지 않는 되돌이 계단으로 구성했다. 기능적으로 연결됐다는 검증이 실제 콘코스 전체를 실측 복원했다는 뜻은 아니다.

## 무대·후면 바닥과 조명 모드

후속 수정에서는 본무대·앞무대·측면 연결대·계단 참을 하나의 외곽선과 같은 UV 축척을 쓰는 단일 무대 메시로 합쳤다. 프로시니엄 벽의 감춰진 하단은 무대면보다 낮춰 목재 윗면과 검은 무대 바닥이 +0.93m에서 겹치지 않게 했다. 2·3층 발코니는 부채꼴 뒤쪽 바닥도 중앙과 같은 직선 접합부까지 연장했고, 중복 카펫 판은 제거했다. 후면 슬래브와 후벽도 측벽까지 닿도록 연결했다. 의도된 층간 계단 구멍은 유지한다.

핀조명 두 대는 사용자 요청에 따라 3층 전면 펜스 앞 브래킷에 부착했다. 본체, 렌즈, 빔, 렌즈 플레어와 실제 SpotLight를 같은 Rig에 연결한다. 과거 후면 객석 쪽에 별도로 남아 있던 핀조명용 안개 발광점은 제거했다. 이 설치 위치는 사용자가 지정한 앱 연출이며 운영사 실측 설치 위치라는 뜻은 아니다.

OPEN PIT은 핀조명 중심의 뮤지컬 조명을 유지한다. OP SEATING은 음원 에너지·시간·팔레트에 따라 무빙라이트, 컬러 워시, 사이드와 전면 조명이 동작하는 콘서트 조명을 사용한다. 두 모드 모두 재생 중 객석등은 어두워진다. 선택 화면에 `Musical lighting` / `Concert lighting`을 표시한다.

## 확인 가능한 한계

도면 좌석 위치·정원·번호와 문서 치수는 근거가 있다. 휠체어·가족실의 개별 중심점, 좌석 가구의 세부 치수, 목재 수종/카펫 제품의 재질 상수, 사진에만 보이는 벽 부재·브리지·난간 상세, 모든 옆 블록의 별도 횡단면은 실측값이 아니다. 공식 평면과 사진을 대조한 재구성이며 실제와 완전히 동일한 실측 모델이라고 표시하지 않는다.

공개 출입구의 평면 위치·폭과 전실은 위 표의 기술도면 기준이다. 기존 자유 이동을 이어 주는 도면 밖 뒤쪽 계단·측면 복도는 공개 범위 안에서 근사한 연결 구조다. 로비·외관·백스테이지 전체의 실측 복원은 이번 범위에 포함하지 않는다.

`src/three/venues/theater-data.js`는 3D 모델, 좌석 선택, 인터랙티브 좌석도에서 공통으로 쓴다. 정적 대체 지도는 `node scripts/theater-map.mjs`로 다시 만든다. 구형 venue-lab 렌더러를 앱 위에 다시 복사하지 않는다.

## 재생성과 검증

```sh
python3 scripts/generate-theater.py /path/to/musical_hall_2025.pdf
node scripts/theater-map.mjs
npm run verify:theater
```

`verify:theater`는 두 모드의 실제 장면을 만들고, 정원·라벨의 유일성·공식 번호 공백·전 좌석/착석 카메라 아래의 층별 바닥·닫힌 발코니 메시·연속 천장면과 기술 개구부 내부 막음·전 좌석 머리 공간·12개 출입구의 실제 메시 개구 폭·측면 문 마감재 잘림·24개 방향별 객석/콘코스 경로·8개 방향별 층간 계단 경로·피트 개구부/덮개를 검사한다. 무대 접합부의 중복 윗면과 두 발코니 뒤쪽 바닥·측벽 접합부도 별도로 훑는다. 실제 Rig의 본체 행렬, 렌즈·빔·플레어·SpotLight 광원 일치, 펜스 앞 설치, 모드별 조명 및 콘서트 에너지·이동 반응을 확인한다. Canvas 텍스트와 GPU 빔 렌더링은 대체하므로 WebGL 픽셀·실제 UI 클릭을 검사했다고 해석하면 안 된다.

추가로 좌석도 React 렌더 결과에서 층별 모든 영문 좌석 버튼과 선택 표시, 기존 360 모드와 새 OP 모드의 구분을 확인했다. 관리형 미리보기는 `relay could not open browser port 4173`로 실패했다. 이후 프로젝트의 기존 Playwright 캡처 방식과 시스템 Chromium의 소프트웨어 WebGL로 실제 수정본을 실행해 객석 전경, 1층 9열 23번 시점, OP 모드 좌석 선택 화면을 촬영했다. 캡처 중 pageerror는 없었다. 소프트웨어 렌더링은 느리므로 실제 GPU 성능 검증으로 해석하면 안 된다. 모바일 터치와 전체 걷기 동선의 실화면 검수는 아직 완료하지 않았다.

발코니·문 개구부·천장 수정 후에도 같은 방식으로 객석 전경, 천장 확대, 1F GATE 1에서 객석을 보는 화면을 다시 촬영했다. 최종 캡처의 pageerror는 0건이다. 캡처용 초기 베뉴만 Theater로 지정했고, 실제 모델·재질·조명·렌더러를 사용했다. 이미지를 보정하거나 합성하지 않았다. 두 피트 모드의 구조 검증과 프로덕션 빌드도 최종 코드로 통과했다.

무대·후면 바닥·핀조명 후속 수정에서는 무대 앞 접합부, 2층과 3층 후면 바닥, 펜스 앞 핀조명 부착부를 각각 Chromium에서 촬영해 확인했다. 캡처 중 pageerror는 0건이다. 재생 조명의 모드별 출력·에너지 반응·무빙과 광원 일치는 실제 Rig를 실행하는 Node 검사로 확인했다. 이 검사를 실제 음원 재생 장면의 픽셀 비교로 해석하지 않는다.
