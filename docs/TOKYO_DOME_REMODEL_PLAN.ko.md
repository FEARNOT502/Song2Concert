## 3. 현재 앱 조사에서 확인한 사실

### 3.1 실제 앱과 실험실의 차이

- 앱의 `td-data.js`를 해독한 데이터와 `venue-lab/pipeline/td_stands.json`은 조사 시점에 동일했다.
- 반면 `src/three/venues/dome.js`와 `venue-lab/src/j-dome.js`는 다르다. 현행 앱에는 신형 전광판의 상단·중앙 하단, 지지 기둥 보정, 발코니 및 특수석 등의 추가 처리가 있다.
- 따라서 오래된 lab 렌더러의 단순 전광판을 현행 앱의 결함으로 분류하지 않는다. 향후 lab 전체 출력을 앱에 덮어쓰면 현행 수정이 사라질 위험이 있다.
- 생성 데이터의 기둥 위치와 실제 렌더링 위치도 같다고 가정할 수 없다. 앱은 전광판 뒤 기둥을 화면과의 간격에 따라 옮기고 일부 기둥의 끝 높이를 재계산한다. 최종 보이는 형상까지 조사 대상이다.

### 3.2 현재 데이터의 규모와 좌석 대조

| 데이터 레벨 | 원시 좌석 레코드 수 |
|---|---:|
| A | 10,357 |
| B | 9,507 |
| F | 5,168 |
| C | 1,801 |
| D | 5,218 |
| E | 8,513 |
| G | 661 |
| 합계 | 41,225 |

이는 현재 생성 데이터의 원시 레코드 수다. 백스크린 좌석 제외, 특수석, 렌더링 필터, 판매 범위가 있으므로 공식 수용 인원 또는 화면에 보이는 좌석 총수로 해석하지 않는다. 일반 상세 PDF에는 발코니 C/스위트와 일부 특수석이 같은 방식으로 포함되어 있지 않아 단순 총합 비교도 부정확하다.

- 앱 라벨과 **기존 전사 JSON**을 읽기 전용으로 대조한 결과, 전사에 존재하는 블록·열 중 560개 조합에서 번호 집합 차이가 있었다. 동일 블록·열·번호의 중복 라벨은 그 비교에서 0개였다.
- 예: 기존 전사상 B02 27열은 461–471의 11석, 앱 라벨은 7석이다. A02 20열 등에서도 차이가 있다. 이는 구조와 좌석 원장을 함께 검수해야 하는 이유다.
- 560개를 확정 오류 건수로 부르지 않는다. 기존 전사 오류, 특수석, 실제 결번, 좌석 누락, 라벨 할당 문제를 분류해야 한다. 렌더링 단계의 좌석 제외까지 포함한 최종 검수는 별도다.
- 기존 전사 자체의 검사도 19개 주의 항목을 출력했다. 좌우 좌석 수 차이를 오류로 단정하는 검사와 지도 라벨 해석 실패가 섞여 있어 원본 판독이 필요하다.
- 특히 `td_chart.py`에는 A01/A49의 일부 불완전·누락 열을 이웃 열로 보간하는 처리가 있다. 사용자 요구가 정확한 열별 수량이므로 이 보간을 사실로 승계하지 않는다.

### 3.3 기둥·보미토리·경사의 조사 대상

- 생성 데이터에는 기둥 64개가 있다. 이 수는 실제 기둥의 확인된 총수가 아니다. 원시 레코드와 전광판 런타임 보정의 관계를 함께 기록해야 한다.
- 내야 기둥 다수는 바닥 10.6m, 끝 15.85m, 단면 반폭 0.6/0.8m로 설정되어 있다. 이 숫자는 현행 모델값이며 실측값이 아니다.
- 사용자 지적처럼 발코니에서 기둥이 안 보이는 문제는 위치·높이·발코니 전후 관계·벽체에 가려지는 상태를 함께 확인해야 한다. 기둥을 일괄 연장하는 것만으로 해결됐다고 판정하지 않는다.
- 현재 F 데이터의 보미토리 레코드는 8개, E는 14개다. 내야 A/B의 출입부는 다른 생성 경로에 있다. `voms` 배열만 세어 전체 출입구 수로 사용하면 안 된다.
- 기존 작업 기록에는 폴 근처 일부 블록을 뒤 콘코스 높이에 맞추며 1.4–7.8m 길이의 수평 부분을 허용한 절충이 명시되어 있다. 현행 세부 형상은 후처리까지 적용되므로 이 기록만으로 현재 뒤틀림의 원인을 확정하지 않는다.
- `td_gen.py`, `td_build.py`의 기본 생성 이후 `td_excite.py`, `td_ends.py`, `td_tidy.py`, `td_steps.py`, `td_balcony.py`가 후처리한다. 한 단계에서 맞춘 단·기둥·끝단이 다른 단계에서 다시 이동·절단되는지 추적해야 한다.
- 재생성에 사용하는 `td_stage1.pkl`, `td_rowsA.pkl`, `td_pre.pkl`, `td_seatlab.pkl`은 현재 체크아웃에 없다. 이를 바로 실패나 영구 누락으로 단정하지 않고, 기존 스크립트에서 재구성할 수 있는지 격리 복사본으로 확인한다. 모델링을 시작하기 전 재현 가능한 생성 순서를 문서화한다.

## 4. 자료를 모델로 옮기는 기준

### 4.1 치수의 신뢰도를 분리한다

각 치수·형상에 출처 URL, 페이지/영상 시각, 촬영 위치, 자료 연도, 적용 구역, 추정법, 신뢰도와 미해결 사항을 붙인다.

| 등급 | 의미 | 처리 |
|---|---|---|
| A | 공식 또는 제작·공급업체의 명시 치수/수량 | 적용 연도·정의를 확인한 후 기준값으로 사용 |
| B | 독립된 복수 사진·영상에서 일치하는 형상 | 사진 정합으로 추정하고 가능한 범위를 기록 |
| C | 한 시점의 사진, 작은 도면, 인접부로부터의 추론 | 임시 추정값으로 관리하고 확대 비교 대상으로 지정 |
| U | 자료 충돌 또는 보이지 않는 연결 | 사실로 채우지 않고 추가 조사 목록에 남김 |

정밀하지 않은 사진에서 소수점 좌표를 얻었다고 실물 치수가 정밀해지는 것은 아니다. 생성 메시에 필요한 정밀도와 실물 치수의 추정 오차를 따로 표기한다. 최신 게시글에 포함된 구형 사진, 개수 전 예상도와 개수 후 실사진도 분리한다.

### 4.2 좌표·평면·단면을 나누어 맞춘다

- 좌석 판매도에서 얻는 블록 순서·열·번호와 실물 평면의 치수를 분리한다. 지도에서 층별로 다르게 그린 축척을 하나로 확대하지 않는다.
- 필드 기준 높이, GL, 층 표기, 앱의 `ZH=114` 위치 오프셋을 명시한다. 서로 다른 원점을 가진 좌표를 섞지 않는다.
- 공식 단면의 치수선을 기준으로 큰 규모를 맞추고, 사진에서는 난간·기둥·보미토리와 여러 열이 함께 보이는 장면으로 비율을 교차 확인한다.
- 광각 왜곡·카메라 높이·시야각을 고려한다. 사진 한 장의 좌석 폭을 무조건 0.5m로 놓아 전체를 역산하지 않는다. 일반석과 익사이트·발코니석의 폭도 구분한다.
- 내야 중앙, 양쪽 측면, 폴 접합부, 외야, 발코니, D/E 끝단의 단면을 별도로 만든다. 하나의 평균 경사로 전체를 맞추지 않는다.

## 5. 부위별 재작업 설계

### 5.1 스탠드 단·단차·열 구조

1. 최신 PDF 원본에서 `블록 → 실제 열 번호 → 좌석 번호 구간들`을 확정한다. 한 열이 나뉘거나 결번이 있으면 단일 연속 구간으로 합치지 않는다.
2. 열별 좌석 수와 방향을 먼저 고정하고, 해당 열이 들어가는 단 깊이·경사를 정한다. 좌석이 안 들어간다고 끝 좌석을 삭제하거나 번호를 다시 붙이지 않는다.
3. 일반 좌석 단, 통로 중간 계단, 넓은 횡통로, 보미토리 양옆 단, 특수석 바닥을 별도 형상으로 다룬다. 좌석 한 열의 높이 차이를 통로 계단 한 단과 혼동하지 않는다.
4. 열이 끝나거나 시작하는 위치, 계단 옆 단의 잘림, 벽과 맞닿는 끝선을 기록한다. 열이 없는 구역에 유령 좌석이나 임의의 수평 관람 단을 만들지 않는다.
5. 열의 높이·위치·좌석 라벨·보행 바닥을 같은 원장에서 만든다. 최종 배치 뒤 위치 기반 최근접 탐색으로 좌석 번호를 추측하는 의존을 줄인다.

### 5.2 A01·A02/B02–외야 경사 접합: 우선 검증 구역

이 구역의 핵심은 **수평 방향의 꺾임을 보존하면서 서로 다른 수직 경사를 올바르게 접합하는 것**이다.

- 기존 모델에서 사용자가 인정한 방향 전환선을 먼저 추출·기록한다. 선 양쪽의 좌석 방향, 열 끝점, 통로 위치를 기준 형상으로 보존한다.
- 내야와 외야 각각의 열 번호·첫 단·마지막 단·경사·뒷단 높이를 독립적으로 추정한다. 두 구역의 같은 내부 행 인덱스가 같은 실제 열이나 높이를 뜻한다고 가정하지 않는다.
- 접합선을 가로지르는 단면을 앞·중간·뒤 여러 위치에서 만든다. 각 단의 윗면이 의도치 않게 비틀리는지, 옆 열을 따라 대각 경사가 생기는지, 실제 단차와 모델 오류를 구분한다.
- 서로 다른 높이의 열을 한 사각형·삼각형 면으로 억지 연결하거나 넓은 구간을 보간해 봉합하지 않는다. 각 구역의 정상적인 단면은 유지하고, 실물에서 확인한 접합선의 계단·단차·벽면으로 연결한다.
- 실제 경계가 평면 하나인지, 꺾인 선인지, 계단식인지 자료로 판정한다. ‘무조건 틈 없이 같은 높이’ 또는 ‘무조건 분리벽’ 같은 해법을 미리 정하지 않는다.
- 뒤 콘코스 높이를 맞추기 위해 전방 단을 끌어올리거나 여러 열을 수평으로 눌러 맞추지 않는다. 뒷단에서 실제 연결 계단이 필요한지부터 확인한다.
- A01/A02/B02–F 경계를 먼저 작은 단위로 검증한 뒤 전체 스탠드로 확대한다. A49/A48/B48 반대편도 독립 검수하며 좌석 수의 좌우 차이를 보존한다.

산출물은 방향 전환선 평면도, 내야/외야 종단면, 접합선 횡단면, 열 높이 표, 기존·수정 비교 화면이다. 이 구역을 통과하기 전에는 전 구역 경사 재생성을 확정하지 않는다.

### 5.3 보미토리

- 외부 게이트 번호, 관객석 통로 번호, 좌석 블록 번호, 실제 보미토리를 별도 식별한다. 지도에 있는 번호 원을 모두 같은 출입구나 같은 기둥으로 취급하지 않는다.
- 내야 A/B 사이 피트형 입구, 외야의 기둥을 사이에 둔 입구, 상단 D/E 사이 입구를 유형별로 구분한다.
- 각 입구에 중심선, 양쪽 개구 폭, 바닥 높이, 피트 길이, 벽 두께, 측벽 높이, 린텔·천장 하단, 터널 깊이, 콘코스 도착 위치를 기록한다.
- 보미토리 위 열은 실제로 유지되는 좌석·슬래브와 빠지는 좌석을 구분한다. 구멍과 난간은 별도로 생성해 벽이 입구를 막거나 상부 단이 틈으로 갈라지는 문제를 방지한다.
- 관객석 쪽과 콘코스 쪽 양방향에서 실제 개구와 연결을 검수한다. 보행 테스트 통과만으로 모양·폭·깊이가 맞았다고 판정하지 않는다.

### 5.4 기둥과 발코니의 관계

- 기둥을 통로 번호 및 인접 블록·벽체·받치는 구조에 대응시키는 목록을 만든다. 원형 번호표 위치와 기둥 중심이 일치한다고 자동 가정하지 않는다.
- 내야 일반부, 폴 근처, 외야 일반부, 전광판 지지부를 나누어 단면과 높이를 추정한다. 전체를 같은 직육면체 규격으로 만들지 않는다.
- 내야는 기둥 앞면/중심선과 발코니 전면·벽면·하부 천장 사이 거리를 재검토한다. 기둥 상단이 어느 면에 만나는지 위·아래에서 모두 확인한다.
- 발코니에서 보이는 기둥의 노출 폭·높이·가림 관계를 실사진과 비교한다. 올바른 위치를 찾은 뒤 기둥 위쪽 접합, 보·벽체와의 마감까지 처리한다.
- 전광판과 충돌한다고 기둥을 런타임에서 임의 이동하는 의존을 줄인다. 확인된 실물 위치를 기준으로 전광판·지지부·통로가 함께 맞게 정리한다.

### 5.5 전광판 하부와 외야 뒤쪽

- 현행 앱의 상단/중앙 하단 화면 구현을 출발점으로 삼는다. 공식 화면 치수, 외야 좌석 마지막 열, 화면 밑 통로·벽체·보·기둥, 백스크린의 관계를 동시에 맞춘다.
- 화면 바로 아래의 빈 공간, 기둥 사이 개구, 천장/소핏, 측면 프레임, 백스크린 양옆 마감과 외야 보미토리 상부를 별도 요소로 조사한다.
- 사진에서 보이는 지지 구조와 추정으로 넣은 팔·보를 구분한다. 화면 뒤 보이지 않는 기계 구조를 임의로 정교하게 만드는 데 범위를 쓰지 않는다.
- 폭·곡률·설치 높이를 맞추려고 기둥·마지막 열·콘코스를 서로 반복해서 움직이는 순환 보정을 없애고 기준 관계를 명시한다.

### 5.6 익사이트석

- G 구역의 좌석 번호·열 수·열별 수량을 1루/3루 별도로 확정한다. 2023년 증설과 현재 PDF를 대조하고 평면 대칭을 강제하지 않는다.
- 앞 펜스, 단의 높이·깊이, 가장자리 대각선, 끝벽, 뒤 통로, 내야로 올라가는 연결 계단과 출입 틈을 함께 맞춘다.
- 앞쪽이 잘리는 블록에서 열마다 좌석 수가 달라지는 형상을 살린다. 공간이 부족할 때 좌석 간격을 극단적으로 줄이거나 단을 내야에 밀어 넣는 방식으로 해결하지 않는다.
- 현재 G 원시 좌석 레코드 661개와 기존 상세 전사 670개 차이는 원본 검수 대상이다. 두 값 중 하나를 검증 없이 정답으로 선택하지 않는다.

### 5.7 난간·벽면·끝단과 하부 천장

- 금속 파이프, 메쉬/유리, 콘크리트 난간벽, 패딩 벽을 구분한다. 모든 경계에 같은 재질·같은 높이의 띠를 두르지 않는다.
- 실제 틈, 출입구, 계단 끝에서 난간을 멈추고, 단차가 변하는 곳에서 연속되는 높이와 끝마개를 처리한다.
- 발코니 및 D/E의 외야 쪽 종료 위치, 돌출 깊이, 옆면, 하부 소핏, 외벽으로 돌아가는 면을 평면·단면에서 함께 맞춘다.
- 얇은 양면 면만으로 벽을 닫지 않고 필요한 두께·윗면·끝면을 만든다. 겹친 면, 떠 있는 슬래브, 보이는 구멍, 불필요한 돌출을 검수한다.
- 재질 조정은 구조가 맞은 뒤 진행한다. 명암으로 가려 구조 오류를 감추지 않도록 조사·검수 화면은 실내등이 켜진 상태도 사용한다.

## 6. 네 콘코스와 계단 연결

사용자 설명의 네 계통을 그대로 요구사항으로 두되, 모델 내부 이름과 실제 건물 층·높이를 분리한다. 특히 외야 통로와 내야 연결은 계단·높이 변화가 있을 수 있으므로 하나의 평평한 링으로 미리 결정하지 않는다.

| 내부 계획 식별자 | 필요한 구역 | 반드시 확인할 연결 |
|---|---|---|
| C1 | 내야 A/B 사이 보미토리 뒤 복도 및 외야 보미토리와 이어지는 계통 | 내야 피트→터널→후면 복도, 외야 입구까지의 실제 연결·고저차·계단 |
| C2 | 내야 최후미 열 뒤의 관객석 쪽으로 열린 콘코스 | 열 뒤 통로와 자유 기둥, 발코니 하부, C1과의 연결 |
| C3 | 3층 발코니 콘코스 | 발코니 좌석 뒤 출입, 양쪽 끝단, 다른 층으로 가는 연결 계단 |
| C4 | 4층 보미토리를 잇는 콘코스 | D/E 입구 뒤 복도, 피트 및 슬래브 하부, 아래 층으로의 계단 |

연결은 `콘코스 구간 → 계단 → 중간참 → 도착 구간 → 보미토리`의 경로 목록으로 관리한다. 실물의 층별 연속 범위와 막힌 끝을 확인하고, 계단을 배치하기 쉬운 빈 곳에 임의로 놓지 않는다. 현장 운영상의 통제와 모델의 물리적 연결은 구분하며, 사용자가 요청한 네 계통 간 이동 가능성을 확보한다.

벽·바닥·천장·계단·중간참과 입구까지 모델링한다. 매점·화장실·라운지 내부는 생략하고, 외부에서 보이는 문·벽체 윤곽은 공간의 폭·방향을 이해하는 데 필요한 수준으로 표현한다. 실내 통로의 마감은 사진의 구분을 살리되 점포 운영 정보나 가구 배치를 재현하는 작업으로 확대하지 않는다.

## 9. 완료 판정

### 좌석

- 확정 원장의 블록·열·번호 집합과 최종 앱 좌석 카탈로그를 전수 비교한다. 열별 수량뿐 아니라 결번·비연속 번호·중복까지 검사한다.
- 모델 데이터에만 있고 렌더러가 지운 좌석, 선택은 되지만 실제 좌석이 없는 경우도 검사한다. 최종 보이는 좌석과 선택 가능한 좌석의 근거를 일치시킨다.
- 원장의 빈칸을 보간하거나 기하 충돌 때문에 좌석을 삭제한 경우를 자동 통과시키지 않는다. 원본 정정·특수석·실제 폐쇄 등 근거가 있는 차이만 별도 승인 사유로 기록한다.

### 형상

- A01·A02/B02–F에서 방향 전환선은 유지되고, 의도하지 않은 단 윗면의 비틀림·대각 경사·자리별 튀는 높이가 없다.
- 각 구역의 열 높이 변화가 근거 단면과 일치한다. 실제 횡통로·계단·특수석 변화가 있는 곳은 정상적인 불연속으로 명시한다.
- 내야 기둥은 발코니 벽체까지의 위치·높이·노출 관계가 자료와 맞고, 전광판 기둥은 프레임과 실제 접합한다.
- 보미토리 양쪽 개구, 단 위·아래, 콘코스 뒤에서 벽·천장·슬래브의 누락이나 관통이 없다.
- 발코니·상단 끝단과 소핏, G석 전후·양끝, 전광판 중앙 하단의 마감을 가까운 거리에서도 확인한다.

### 이동과 성능

- 네 콘코스와 연결 계단을 경로별로 양방향 이동한다. 문 앞·계단 시작/끝·중간참·층 도착부의 걸림과 머리 충돌을 확인한다.
- A01·A02/B02와 외야 연결, 내야/외야 보미토리, 상단 14개 입구를 포함한 실제 목록 전체를 검사한다. 현재 배열 수를 검증 대상의 정답으로 사용하지 않는다.
- 모든 수정 대상 좌석이 올바른 단 위에 있고, 좌석 선택 시 카메라가 바닥·벽·기둥 내부에 들어가지 않는지 확인한다.
- 현재 앱의 PC 품질을 기준으로 같은 기기·같은 카메라에서 메모리, 드로콜, 프레임 시간, 초기 생성 시간을 비교한다. 소프트웨어 렌더링 환경 수치만으로 일반 PC 성능을 보장하지 않는다.
- 실제 변경 후 앱 빌드와 필요한 기존 검증을 수행한다. 공통 렌더러·보행 변경이 있으면 영향을 받는 다른 회장을 확인한다. 조사 단계에서 빌드 통과를 모델 수정 완료로 보고하지 않는다.

대표 비교 시점은 내야 중앙 전/중/후열, A01·A02/B02 접합부 전/중/후, 반대편 접합부, 외야 일반/중앙, 발코니 전/후열과 폴 끝, D/E 입구와 양끝, G석 홈/중간/폴 끝, 네 콘코스 및 계단 도착부다. 사진과 비교할 때 카메라 높이·방향·시야각을 함께 기록한다.
