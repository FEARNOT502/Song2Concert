# 베뉴 피커 개선 계획서

작성 2026-11-07 · 상태: 구현됨. 계획에서 달라진 점은 9절

## 1. 범위와 정해진 것

네 가지를 한 번에 다룬다.

1. **베뉴 피커**: 3×2 카드 그리드를 **왼쪽 목록 + 오른쪽 큰 미리보기** 구조로 바꾼다.
2. **좌석배치도**: 3D 장면을 래스터로 뽑던 방식을 **구역(블록) 단위 벡터 도면(SVG)**으로 바꾼다. 모든 공연장이 같은 팔레트를 쓴다.
3. **물음표 버튼**: 상단바 오른쪽 끝 `?` 버튼은 그대로 두고, 원 안의 `?` 글자만 정중앙에 맞춘다.
4. **Club 관객**: 300명 스탠딩을 **꽉 차게** 채운다. 무대 앞이 빽빽하고 바 쪽으로 갈수록 성기다. 다른 공연장처럼 Scene effects를 끄면 관객도 사라진다.

**하지 않는 것**

- 사운드는 바꾸지 않는다. Club 관객은 화면에만 추가하고 룸 모델이나 IR은 건드리지 않는다.
- 공연장 이름은 지금처럼 Arena, Dome, Stadium으로 둔다. 실제 모델이 된 공연장 이름은 드러내지 않는다.
- 3D 공연장 모델은 고치지 않는다. 배치도는 모델에서 읽어 오기만 한다.
- 관객과 걷기(WASD) 사이의 충돌 처리는 넣지 않는다.

## 2. 지금 상태에서 보이는 문제

**피커**

- 카드를 누르면 바로 입장한다. 미리 살펴볼 단계가 없다.
- 카드에는 이름, 수용 인원, 장르 문구만 있다. `data.js`가 이미 계산해 둔 RT60, 청취 거리, 첫 반사 같은 값은 피커에 나오지 않는다.
- 360 배치도는 마우스를 올려야만 보이므로 터치 기기에서는 볼 수 없다.
- Club의 수용 인원이 `300 seats`로 표시된다. 실제로는 스탠딩이다.
- 키보드로 공연장을 고를 수 없다. 지금은 `V`로 피커를 여는 것까지만 된다.
- 6장이 한 화면에 들어가도록 맞춘 탓에 카드 속 배치도가 작아서 잘 읽히지 않는다.

**배치도** (`public/venue-maps/*.webp`, `scripts/venue-maps.mjs`)

- 좌석 메시 색을 그대로 써서 공연장마다 색이 다르다. 아레나는 회색, 스타디움은 빨강, 돔은 파랑, 홀은 살구색이다.
- Club은 갈색 사각형 위에 주황 무대 하나뿐이다.
- Arena 360은 스탠딩 판정이 무너져 화면 절반에 대각선으로 갈색이 칠해진다.
- Stadium은 오른쪽에 대각선 잔선이 지나간다. 무대 외 구조물이 섞여 들어간 것으로 보인다.
- Theater는 무대 위쪽이 잘리고, Dome은 외야 상단 좌석이 잘린다.
- Concert Hall은 무대 위 오케스트라 의자와 보면대가 좌석으로 잡혀 노이즈가 생긴다.
- 래스터(960×540)라서 큰 미리보기로 키우면 흐려진다.

**물음표 버튼** (`src/components/SoundInfo.jsx:48-57`)

- `font-mono` + `leading-none` + `text-[12px]` 조합에서 `?` 글리프가 글꼴 메트릭 때문에 원 안에서 위나 옆으로 치우친다.

**Club** (`src/three/venues/club.js:200`)

- `// no audience: the floor is empty` 주석대로 관객이 없다. 다른 공연장이 쓰는 관객 유니폼(`cu`)은 이미 있다.
- 방 크기는 12 × 16 m이고 무대 앞단은 z = 3.5, 카메라 눈 위치는 z = 6.3, 바는 뒷벽 z ≈ 15.8이다.

## 3. 베뉴 피커 개선안

### 3-1. 레이아웃

```
┌───────────────┬──────────────────────────────────┐
│ ● Club    300 │  [ GENERAL | 360 ]       ← 큰 방만 │
│   Theater 1.7k│  ┌────────────────────────────┐  │
│   Hall    2.0k│  │        배치도 (SVG)         │  │
│ ▸ Arena  22.5k│  │                            │  │
│   Dome    45k │  └────────────────────────────┘  │
│   Stadium 90k │  ARENA · 22,500 seats            │
│               │  RT60 · 청취 거리 · 첫 반사 · 형태 │
│               │                      [ 입장 → ]  │
└───────────────┴──────────────────────────────────┘
```

- **왼쪽 목록**: 작은 곳부터 큰 곳 순서. 각 행에 이름, 수용 인원(축약), 지금 공연장 표시 `●`. 행 앞에 작은 규모 막대를 넣어 300명과 9만 명의 차이를 한눈에 보이게 한다.
- **오른쪽 미리보기**: 큰 배치도, 장르 문구, 핵심 수치 4개, 입장 버튼.
  - 수치: RT60, 청취 거리, 첫 반사(ITDG), 형태(스탠딩/좌석/혼합). 모두 `data.js`에 있는 값이고 새로 계산하지 않는다.
- **GENERAL / 360 탭**: Arena, Dome, Stadium에서만 미리보기 위에 보인다. 탭을 누르면 미리보기만 바뀌고, 입장은 입장 버튼으로 한다. 터치 기기에서도 360을 볼 수 있다.
- 피커를 열면 지금 공연장과 그 모드가 선택된 채로 열린다.

### 3-2. 고르기와 입장

| 동작 | 결과 |
| --- | --- |
| 목록 행 클릭 / ↑↓ | 미리보기만 바꾼다 |
| 행 더블클릭 / Enter / 입장 버튼 | 그 공연장과 모드로 입장하고 피커를 닫는다 |
| ←→ (큰 방에서) | GENERAL / 360 전환 |
| Esc / 바깥 클릭 / ✕ | 닫기(지금과 같음) |

지금은 한 번 클릭하면 바로 입장했는데, 이제는 한 단계가 늘어난다. 대신 더블클릭과 Enter로 지금처럼 빠르게 들어갈 수 있다.

### 3-3. 모바일 (< 640px)

- 목록은 위쪽에 가로 스크롤 칩으로 둔다. 칩에는 이름과 수용 인원이 들어간다.
- 그 아래에 미리보기, 수치, 입장 버튼을 세로로 쌓는다. 입장 버튼은 화면 하단에 붙인다.
- 모달 높이는 지금처럼 `92vh` 안에 들어가게 한다.

### 3-4. 같이 고칠 것

- Club 수용 인원 표시를 `300 standing`으로 바꾼다(`data.js`).
- 목록에 `role="listbox"`와 `aria-selected`를, 탭에 `aria-pressed`를 넣는다. 배치도 `alt`는 지금처럼 둔다.

## 4. 좌석배치도 재작업 (벡터)

### 4-1. 그리는 것

| 요소 | 표현 |
| --- | --- |
| 무대 (런웨이·돌출 포함) | 강조색 `#ff9745` 면 |
| 좌석 블록 | 층별 회색 단계 면 + 블록 사이 얇은 틈. 위층일수록 밝게 |
| 플로어 좌석 블록 | 같은 회색 계열 사각형, 라벨(F1…) |
| 스탠딩 구역 | 강조색을 어둡게 한 면, `STANDING` 라벨 |
| Club의 바, FOH | 짙은 회색 윤곽선 + 작은 라벨 |
| 층 이름 | 블록 위에 작은 라벨(200, 300 …). 겹치면 생략 |

- 모든 공연장이 이 팔레트 하나를 쓴다. 좌석 실제 색은 쓰지 않는다.
- 무대는 늘 위쪽에 둔다(지금 규칙 유지). 360은 무대가 가운데 온다.
- 여백과 선 굵기는 공연장 크기와 관계없이 화면 기준으로 같게 맞춘다.

### 4-2. 만드는 방법

`scripts/venue-maps.mjs`를 고쳐 지금처럼 실행 중인 dev 앱에서 읽되, 출력을 `public/venue-maps/<id>.svg`로 바꾼다. 수작업 도면이 아니라 생성물이므로 공연장 모델이 바뀌면 다시 돌리면 된다.

1. **블록 데이터 꺼내기**: `stands.js`는 관객이 켜져 있을 때 이미 좌석마다 블록 번호를 매긴다(`seatBlocks`/`aisleBlocks`, `stands.js:1343`). 이 결과(층 이름, 블록 번호, 좌석 x/z)를 `root.userData.plan`에 남기는 디버그 훅을 추가한다. 화면에는 영향이 없다.
2. **블록 윤곽**: 블록마다 좌석 점에서 오목 외곽선(concave hull)을 구하고 살짝 부풀린다. 같은 층의 단(tread) 폴리곤으로 잘라 계단 모양을 살린다.
3. **무대, 플로어 블록, 스탠딩**: 무대는 지금처럼 `userData.plan === 'stage'`인 메시에서 위를 보는 면을 모아 합친다. 플로어 블록은 `show.js`의 `floorBlocks`에서 나온 사각형을 쓴다. 스탠딩은 공연장별로 명시한 사각형/다각형으로 그린다. 지금처럼 좌석 링으로 추정하지 않으므로 Arena 360 버그가 원천적으로 사라진다.
4. **Theater, Club**: 데이터 파일이 없는 손모델이다. Theater는 좌석 점에 `aisleBlocks`를 돌려 블록을 만든다. Club은 방, 무대, 바, 스탠딩 구역을 직접 정의한 다각형으로 그린다.
5. **정리**: 좌표를 소수 1자리로 반올림하고 가까운 점을 단순화해 파일당 수십 KB 이하로 만든다.

라벨 글꼴: `<img>`로 넣은 SVG는 웹폰트를 불러오지 못하므로 `font-family: ui-monospace, monospace`를 쓴다. 차이가 거슬리면 SVG를 인라인으로 넣는 쪽으로 바꾼다.

### 4-3. 확인할 미지수 (4단계 첫 작업)

- `seatBlocks` 결과가 도면에 쓸 만큼 깔끔한지. 조명 제어용이라 자투리 블록이 생길 수 있다. 결과가 지저분하면 `minSeats`를 올리거나 도면 전용으로 작은 블록을 이웃에 합친다.
- 오목 외곽선 계산을 직접 짤지, 개발 의존성(`concaveman` 등)을 쓸지. 스크립트 전용이라 앱 번들에는 들어가지 않는다.
- Stadium의 대각선 잔선 원인. 벡터 방식에서는 위를 보는 면을 무대에만 쓰므로 함께 사라질 것으로 예상하지만, 생성 결과로 확인한다.

## 5. 물음표 버튼

- `?` 문자 대신 16×16 SVG 아이콘으로 그려 글꼴 메트릭과 상관없이 정중앙에 오게 한다. 색은 `currentColor`라서 지금의 호버/열림 색 전환이 그대로 먹는다.
- 버튼 크기 `w-6 h-6`, 원 테두리, 위치는 바꾸지 않는다.
- 확인: 데스크톱 상단바와 모바일 레이아웃에서 확대 캡처해 상하좌우 여백이 1px 안쪽으로 같은지 본다.

## 6. Club 관객

- `club.js:200`의 빈 자리에 스탠딩 관객을 넣는다. 다른 공연장과 같은 `people.js`의 `crowd3D(..., { kind: 'floor' })`을 쓰고, 배치는 `show.js`의 `packFloor`로 한다.
- **밀도**: 무대 앞(z 3.8–6)은 간격 약 0.5 m로 빽빽하게, 가운데(z 6–11)는 0.62 m, 바 앞(z 11–14)은 듬성듬성. 합계 약 280–300명.
- **비워 둘 곳**: 카메라 눈(z = 6.3) 주변 반경 약 0.45 m, 바 카운터 앞 1 m, 출입구 동선, PA와 장비 자리.
- **켜고 끄기**: `q.crowd`가 꺼져 있으면(Scene effects off) 넣지 않는다. 저사양(`quality: 'low'`)에서는 다른 공연장처럼 줄인다.
- **조명**: 이미 있는 `cu.uRimColor`/`uWash`/`uAmb` 갱신이 관객에도 먹는지 확인한다. 무대 앞 머리 실루엣이 역광으로 보이는 것이 목표다.
- 확인: 기본 시점에서 앞사람 머리가 무대 하단을 가리되 밴드와 LED 벽은 보이는지, 프레임 시간이 다른 공연장보다 크게 늘지 않는지.

## 7. 작업 순서

서로 의존이 적은 순서로 간다. 각 단계는 따로 커밋한다.

| 단계 | 내용 | 끝났다고 볼 기준 |
| --- | --- | --- |
| 1 | 물음표 버튼 | 데스크톱·모바일 확대 캡처에서 정중앙 |
| 2 | Club 관객 | 기본 시점 캡처, effects on/off 전환, 프레임 시간 비교 |
| 3 | 배치도 생성 스크립트 → SVG 9장 | 9장 모두 잘림·잔선·대각선 없음, 같은 팔레트, 파일당 ≤ 60 KB |
| 4 | 피커 재구성 (3-1 ~ 3-4) | 마우스·키보드·터치로 고르기와 입장, 360 미리보기, 모바일 폭 375px에서 가로 스크롤 없음 |
| 5 | 전체 확인 | `npm run build` 통과, 브라우저에서 6곳 × 모드 입장 확인 |

3단계와 4단계가 가장 크다. 4단계는 3단계 결과물이 없어도 기존 webp로 먼저 만들 수 있으므로, 3단계가 길어지면 순서를 바꿔도 된다.

## 8. 남은 결정 (구현 중에 정해도 되는 것)

- 목록 행의 규모 막대를 로그 스케일로 할지 선형으로 할지. 선형이면 Club이 거의 안 보이므로 로그를 기본으로 한다.
- 미리보기 수치 4개의 정확한 문구와 단위. `SoundInfo` 팝업의 표기와 맞춘다.
- 기존 `*.webp` 9장은 SVG로 대체한 뒤 지운다.

## 9. 결과와 계획에서 달라진 점 (2026-11-07)

- **물음표 버튼, Club 관객, 피커**: 계획대로 구현했다. Club 관객은 303명이고, 기본 시점 바로 앞은 비워 두었다. 피커 지도는 휠, +/− 버튼, 더블클릭으로 확대할 수 있다.
- **배치도는 벡터 블록 도면 대신 원래 방식을 SVG로 바꿨다.** 블록 외곽선을 다시 그리는 방식은 윤곽이 울퉁불퉁하게 나와서 사용자 요청으로 접었다. `scripts/venue-maps.mjs`는 예전처럼 장면에서 바닥과 단(높이별 8단계), 좌석 점, 무대를 읽는다. 바뀐 것은 출력이 SVG라는 점과, 모든 배치도를 세로로 긴 1080×1440으로 통일했다는 점이다(무대가 가운데인 360 배치는 긴 변이 세로로 가게 돌린다). 같은 높이 단계의 삼각형은 겹치는 변을 지워 외곽선으로 합쳐 크기를 줄였다(Wembley 1.2 MB, gzip 260 KB).
- 같이 고친 원래 방식의 문제:
  - Arena 360 대각선: 스탠딩 바닥을 좌석 고리 안쪽으로 잘라(clipPath) 그린다.
  - Theater 무대와 Dome 외야가 잘리던 문제: 화면 범위를 관객 0.1–99.9 %와 무대 전체로 잡는다.
  - Stadium 잔선: 길고 가는 삼각형을 뺀다.
  - Concert Hall 무대 위 의자 노이즈: 무대(플랫폼)를 `userData.plan = 'stage'`로 표시해 그 위를 덮는다.
- **블록 라벨은 넣지 않았다.** 공식 배치도(venue-lab/pipeline의 원본 데이터)와 앱 블록을 대조한 결과는 다음과 같다.
  - Dome: 1층 블록이 공식 도면과 일치한다(A 49/49, B 43/45, F 20/20).
  - Arena: 앱 블록이 공식 블록 여러 개를 묶은 단위다. 공식 블록을 가로지르는 경우는 거의 없다.
