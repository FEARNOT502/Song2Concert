## 작업 순서

1. **기준 뷰를 맞춘다.** 공식 좌석도와 1F–5F 도면에서 바닥 네 모서리, 문·통로 중심선, 첫·마지막 열과 발코니 끝을 표시한다. 앱 좌표의 `−z`는 무대 쪽이므로 현장의 방위는 공식 지도에서 출입구와 무빙 블록을 기준으로 맞춘다. 사진은 공연·촬영 위치·좌석 가동 상태를 기록한다. 원근을 맞출 때는 문 중심, 통로 모서리, 발코니 끝처럼 두 화면에서 식별되는 기준점을 세 곳 이상 사용한다. 408·430번 좌석의 사진, 200레벨 양쪽 장변, 바닥 네 코너와 3F·5F 정면을 같은 시점과 화각으로 비교한다.
2. **객석 뒤 벽과 개구부를 맞춘다.** 400레벨 네 코너와 200레벨 211·212·219·239를 먼저 고친다. 객석 쪽 벽, 옆벽, 인방과 슬래브를 맞추고 각 층의 단순 통로와 연결한다. 이어 1F 바닥과 네 코너 개구부를 연결한다. `ssa_gen.py`의 기존 SSA 생성 경로에서 변경하고, 실제 앱이 읽는 `ssa-data.js`를 갱신한다. [SSA 구조 생성](../venue-lab/pipeline/ssa_gen.py) · [앱 구조 데이터](../src/three/venues/ssa-data.js)
3. **객석 전면과 난간을 맞춘다.** 코너의 절개선·터널 입구를 확정한 뒤 펜스를 얹는다. 300·500레벨 끝벽을 공통 단면에서 생성하고 300레벨의 별도 끝벽을 정리한다. 200·400레벨 계단 손잡이, 발코니 파라펫과 스위트 유리를 추가하고, 좌석 블록 및 피커와 대조한다. [앱 공통 객석 렌더러](../src/three/stands.js) · [Arena 블록 지도](../src/components/ArenaBlockMap.jsx)
4. **상부 구조와 마감을 맞춘다.** 천장 패널·트러스·조명 위치를 먼저 확정한 뒤, 실내에서 보이는 무빙 블록 접합부와 400레벨 뒤 확산 패널, 스위트 전면과 객석 마감을 적용한다. 공연 조명으로 벽과 난간이 가려질 수 있으므로 하우스 조명을 켠 상태를 구조 검수 기준으로 삼고, 일반·360 공연 화면도 확인한다.

## 검수 기준

- 공식도에 있는 출입구 94개에서 앱의 문틀·진입 터널, 착지면, 콘코스 연결을 각각 확인한다. 실사로 확인한 통로는 양방향 보행을, 벽과 펜스는 서로 다른 각도의 접근에서 충돌을 검증한다. 기존 복도 닫힘 검사에는 도면에서 확인한 개구부와 실제 문을 반영한다. [앱 보행 충돌 코드](../src/three/walk.js) · [콘코스 닫힘 검사](../venue-lab/pipeline/ssa_closure.py)
- 수정 전후 같은 좌석에서 문, 난간 상단, 첫·마지막 열, 발코니 끝, 천장 경계가 사진의 기준점과 맞는지 확인한다. 보행 검수는 문 양쪽과 층간 착지면, 시야 검수는 앉은 눈높이에서 수행한다. 대표 지점은 211·219·239, 407·408·414·425·431·432, 300·500 발코니 양 끝, 네 바닥 코너와 스위트다.
- 일반·360에서 좌석 번호와 블록 선택, 입장 위치, 무대 마스킹, 조명과 천장 간섭을 다시 확인하고 `npm run build`를 통과한다. 400레벨 코너 벽 상단의 실측, 터널 안쪽 단면, 3F 스위트 전면 평면, 42개 천장 세트의 배치도는 공개 자료로 확인한 범위까지 반영하고, 남은 추정 치수는 근거와 함께 기록한다.
