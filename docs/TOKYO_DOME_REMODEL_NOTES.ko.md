# 도쿄돔 내부 재작업 구현 기록

대상은 실제 앱의 `src/three/venues/dome.js`다. 초기 조사·요구사항은 [조사·계획서](TOKYO_DOME_REMODEL_PLAN.ko.md), 확보한 PDF 주소·해시는 [자료 목록](references/tokyo-dome-2026-sources.json)에 있다.

## 형상과 원장

- 내야 단의 앞·뒤 선은 10cm 격자의 윤곽을 그대로 따라가지 않고 해석적인 직선·곡선으로 만든다. A01·A02/B02의 의도된 방향 전환선에는 꼭짓점을 넣어 보존한다. 높이는 각 단에서 일정하며, 서로 다른 경사를 잇는 접합선에 맞추려고 단 자체를 비틀지 않는다.
- 거리장은 정확한 유클리드 거리와 작은 평활화를 사용하고, 좌석 곡선은 격자 사이를 연속 보간한다. 외야 폴 블록의 직선과 다음 블록의 곡선은 같은 위상을 사용한다. 앞선이 펜스를 관통하지 않게 곡선 펜스 전체를 기준으로 위치를 잡는다.
- 외야 뒤쪽은 PDF의 21열 및 후면 보행 단을 담는 깊이로 생성한다. 좌석도 외곽이 얕거나 한 구석이 빠졌다고 마지막 열을 앞 단에 올리지 않는다. 블록의 뒤 열이 끝날 때도 이웃 통로가 갑자기 옆으로 이동하지 않게 연속된 외곽을 기준으로 배치한다.
- `td_rows_real.py`는 최신 확보 PDF를 다시 읽는다. 반복 텍스트의 좌표를 0,0으로 잘못 반환하던 pypdf 방문자 처리는 MuPDF의 실제 기준선 좌표로 보완했다. 좁은 셀의 수동 판독 예외는 코드에 명시했다. A01의 빈 열을 이웃 열로 보간하지 않으며, B22/B28의 PDF 밖 열을 임의로 추가하지 않는다.
- 좌석을 통로나 기둥과 겹친다는 이유로 삭제한 채 끝내지 않는다. 완성된 단·개구부를 기준으로 열 전체를 다시 배치하고, 블록·열·번호 구간을 원장과 대조한다. 충분한 공간이 없으면 생성이 실패하도록 한다.
- 내야 끝 B02/B48의 열 깊이는 실제 원장의 마지막 열을 담도록 조정한다. B03/B47의 뒤 열은 먼저 끝나는 이웃 블록 쪽 빈 쐐기 공간으로 연장하고, 단 높이가 일정한 끝단으로 마감한다.
- 게시 전 기존 `main`의 조명 간섭 수정과 상단 끝 열 정렬을 병합했다. D01/D51 끝 마감은 기존 `main`의 `D_END` 기준을 유지한다. `td_seat_gaps.py`의 결번 추정 연장은 호출하지 않으며, 이번 완전 원장 배치·검증으로 대체한다.

## 기둥·보미토리·콘코스

- 내야 지지 기둥은 발코니 벽면에 맞추고, 하부 지지대와 위쪽 벽면의 얇은 기둥 부분을 나누어 표현한다. 기존의 떨어진 장식 기둥과 중복시키지 않는다.
- 벽면에는 기둥의 중심이 아니라 보이는 앞면을 맞춘다. 내야 하부 단면 0.6×0.8m, 상부 단면 0.6×0.4m는 사진에 따른 추정이다. 벽을 따라 인접한 열의 수용량을 함께 검사한 뒤 위치를 소폭 조정한다. 번호판도 단면 앞·뒤 면에 붙인다. 기둥과 좌석의 실제 방향·폭·깊이·높이를 별도로 대조한다.
- 외야 기둥과 보미토리는 앞 열의 통로 중심만으로 정하지 않는다. 양쪽 뒤 열의 실제 좌석 결번이 서로 다르므로, 원장에 남는 공간을 기준으로 중심을 조정한다.
- C1은 내야 A/B 출입부 뒤 통로와 후면 하부 연결부, C2는 1층 마지막 열 뒤 열린 통로, C3는 발코니 뒤 통로, C4는 상단 보미토리 뒤 통로다. 지지 바닥과 천장을 갖추고 층간 계단을 연결한다.
- 후면 하부 통로 위 바닥은 필드까지 꽉 찬 콘크리트가 아니라 지붕 슬래브로 만든다. 발코니 뒤에는 칸막이가 이동을 가로막지 않는 연속된 보행 폭을 확보한다.
- 계단 구멍은 구조 슬래브뿐 아니라 밝은 복도 바닥과 천장에도 함께 뚫는다. 발코니 방의 뒤 벽·칸막이도 출입 부분을 연다. 계단 옆 난간의 위·아래 선은 계단 경사를 따른다.
- 중앙 3층–4층 연결 계단은 라운지 천장과 겹치던 위치에서 뒤쪽 서비스 통로로 옮기고 3층 연결 발판을 마련한다. 이 계단의 정확한 실물 평면 위치는 미확정 추정이다.
- 외야 양쪽에는 기존 보미토리 뒤 2.4m 통로를 침범하지 않는 하부 콘코스 연결 계단을 둔다. 이 두 계단의 세부 위치도 추정이다. C1 보행 경로는 계단 몸체를 돌아가며, 외야 보미토리에는 실제로 오를 수 있는 단과 끊기지 않는 시작·끝 발판을 만든다.

## A02 터널

추가 확인한 자료:

- [A02 2통로 41열, A03 3통로 46열의 홈 방향 사진](https://www.aoimahiroblog.tokyo/tokyo-dome-view-infield1f/): 터널 위 열린 공간과 꺾인 회색 벽, 은색 펜스의 관계. 구형 전광판이 보이므로 영구 구조 참고로 한정한다.
- [2019년 라이트 폴 근접 사진](https://ameblo.jp/wwwa-s/entry-12546650996.html): 인접 좌석·난간·촬영 구역의 재료와 비율. 이 사진을 터널 전면을 직접 촬영한 사진으로 취급하지 않는다.
- 2026년 상세 PDF의 A02 첫 좌석 열은 20열이다. 이 앞선을 이용해 열린 공간의 뒤쪽 사선 경계를 정한다. A48에 같은 터널을 복제하지 않는다.

기존의 고정 2.8m 열린 구간을 좌석 앞선까지 늘리고, 양쪽 벽이 서로 다른 위치에서 지붕에 닿도록 만든다. 철제 펜스는 벽의 높이·경사를 따라 상부 관, 기둥, 망으로 구성한다. 벽·바닥은 사진의 밝은 회색과 중간 회색으로 조정한다.

사용자의 추가 지시에 따라 펜스 높이는 1.05m에서 **0.6m**로 낮췄다. 그라운드 방향 전면 펜스는 제거하고 좌우·뒤쪽 **3면**만 남겼다. 0.6m는 이번 시각 조정값이며 실측값이라는 의미는 아니다.

공식 360°는 공유 Chromium에서 `Browser not supported / WebGL` 오류, YouTube는 `ERR_TUNNEL_CONNECTION_FAILED`로 화면 확인이 막혔다. 영상 내용을 확인한 것처럼 근거로 쓰지 않는다.

## 추정과 미확정

| 항목 | 판단 수준·범위 |
|---|---|
| 일반 A/B/F/D/E/G 번호 원장 | 2026년 상세 PDF 전사와 대조. 공급자가 공식 실측 좌석 원장을 보증하는 자료는 아니다. |
| C/S 개별 번호 및 일부 특수석 배치 | 같은 수준의 최신 상세 원장을 확보하지 못했다. 기존 추정 배치를 최신 확정값이라고 표시하지 않는다. 2022년 납품 수량 1,520+284석도 현재 수량으로 단정하지 않는다. |
| 층 경사·단 깊이 | 공식 구조 단면과 사진, 열 수에 맞춘 추정. 국부 단차 약 ±0.05–0.10m, 단 깊이 약 ±0.10–0.15m를 검토 범위로 둔다. 실측 허용오차가 아니다. |
| 내야 기둥 | 벽면 정렬 관계는 사진으로 판단. 평면 위치 약 ±1–2m, 단면 약 ±0.15–0.20m, 층 접합 높이 약 ±0.5m의 추정 검토 범위. 실측 도면으로 확정한 치수가 아니다. |
| C1 연속 통로·C3 뒤 보행 폭 | 외곽·폭과 가려진 연결은 추정. 매점·화장실·라운지 실내 세부는 추가하지 않는다. |
| 뒤쪽 서비스 계단 | 실제 평면 위치는 미확정. 현재 모델에서 네 계통을 걸어서 연결하는 구조로 만든다. |
| A02 터널 | 개구부 사선과 20열과의 관계는 사진·원장으로 판단. 유효 폭·높이 각각 약 ±0.4m, 가려진 내부 길이 약 ±2m, 펜스 높이 약 ±0.15m의 추정 범위. |
| 색 | 최신 좌석 전체 파란색은 사용자 지정. 콘크리트·벽·철제부는 사진 기준이며 현장 조명·촬영 화이트밸런스로 차이가 남는다. |

## 재생성과 검사

Python에는 numpy, scipy, opencv-python-headless, scikit-image, shapely, pypdf, PyMuPDF가 필요하다. 가상환경을 권장한다. 생성 명령은 `venue-lab/pipeline`에서 실행한다.

```sh
python td_rows_real.py       # 최신 상세 PDF 원장. TD_PDF_DIR로 확보한 원본을 지정 가능
python td_rowsA.py
python td_gen.py
python td_build.py           # 후처리·번호 검증·app/lab 데이터 출력까지
python -m unittest test_td_geometry.py
python verify_td_model.py
```

`TD_APP_DATA`를 지정하면 실제 앱 파일을 덮어쓰기 전에 다른 경로로 출력할 수 있다. `td_pre.pkl`과 `td_seatlab.pkl`이 있으면 `python td_post.py`로 후처리부터 다시 실행할 수 있다. 이미 라벨을 출력한 JSON에 `td_labels.py`만 반복 실행하는 방식은 사용하지 않는다.

실제 앱의 충돌 검사와 화면 캡처:

```sh
CHROMIUM_PATH=/usr/bin/chromium node scripts/verify-dome.mjs /tmp/dome-review --screenshots
npm run build
```

`verify_td_model.py`는 원장의 모든 번호 집합, 중복 번호, 유효하지 않은 단 폴리곤, 바닥에서 벗어난 좌석, 근접 중복 좌석과 기둥·등받이 형상 교차를 검사한다. `verify-dome.mjs`는 실제 앱의 Walker로 계단·보미토리와 콘코스 경로를 검사한다. `--views=A02-tunnel,outfield-side,scoreboard`로 캡처 구역을 한정할 수 있다.

## 최종 검사 결과

- 최신 확보 PDF와 대조한 **233개 블록·3,536개 열·40,073개 좌석 번호**: 번호 집합 차이 0, 중복 0. 상단 6페이지 이미지 원장은 수동 전사이며, 텍스트 PDF 13종은 재파싱 결과가 기존 원장과 일치했다.
- 전체 모델 좌석 레코드 42,101개: 단에서 벗어난 좌석 0, 30cm 이내 중복 위치 0, 기둥과 등받이 형상 교차 0, 유효하지 않은 단 폴리곤 0. 이 합계는 **실제 도쿄돔의 공식 수용 인원이라는 의미가 아니다**. C/S 및 일부 특수석 2,028개는 위의 상세 원장 검증 범위 밖이다.
- 실제 앱 보행 검사 **89/89 통과**: 층간 계단 13개 양방향, 상단 보미토리 14개 양방향, 외야 보미토리 8개의 기둥 양옆 양방향, C1 순환·C3 후면·C4 후면 경로. 이 검사는 모든 좌석에서 출발하는 전수 보행 증명이 아니다.
- 형상 회귀 검사 5개 및 `npm run build` 통과. A02·접합부·발코니·외야·전광판 화면 확인.
- 소프트웨어 WebGL로 기능·화면을 확인했다. 실제 PC 그래픽카드의 FPS·프레임 시간은 측정하지 않았다.

기계 판독용 결과와 생성 데이터 해시는 [검수 요약](references/tokyo-dome-2026-checks.json)에 기록한다. C/S 상세 번호 및 가려진 내부 치수는 위 미확정 목록을 유지한다.
