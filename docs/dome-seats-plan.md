# 도쿄돔 스탠드 좌석 재구성 계획서

작성 2026-11-07 · 상태: 계획. 아직 구현하지 않음

## 1. 목표와 정해진 것

도쿄돔 스탠드의 블록별 열 수와 열별 좌석수를 실제와 최대한 같게 다시 만든다.

- **범위**: 1층 내야 A(A01–A49, 1–26열)·B(B02–B48, 27열부터), 2층 D(D01–D51, 1–10열, 스카이테라스 포함)·E(E06–E46, 11열부터), 외야 F(F01–F20), 익사이트석 G.
- **제외**: 발코니(C)는 자료가 없어 지금대로 둔다. 그라운드(필드) 블록은 이번에 손대지 않는다.
- **자료**: 팬 사이트 kurumicat의 블록별 상세 좌석표(열마다 첫 번호와 끝 번호)를 쓴다. 공식 좌석표 PDF에서 읽어 둔 블록별 열 범위와 시작 번호(`td/td_labeled.json`)와 대조해 서로 어긋나는 곳은 목록으로 남긴다.
- **단 길이까지 수정한다**: 각 열의 단(tread)을 실제 좌석수에 맞는 길이로 다시 깐다.
- 같이 고칠 것:
  1. 외야에 가까운 1층 블록이 위로 갈수록 경사가 완만해지는 문제
  2. 전체적으로 단차가 블록마다, 열마다 고르지 않은 문제
  3. 익사이트석 펜스가 깨지는 문제
- **주의**: 단차를 바꾸면 외야와 가장 가까운 블록(폴 쪽 A01/A49, A02/B02, F20/F01, 코너 K면)에서 모델링이 자주 깨졌다. 이 구역은 단계마다 따로 확인한다.
- **원칙**: 바꾸고 나서 모델링이 이상해지면 그 부분은 바꾸지 않는다. 이전 지시와 같다.

## 2. 지금 상태

- 좌석은 공식 PDF의 블록 외곽선 안에 0.5 m 간격으로 자동 배치한 것이다(`td_stand1.lay_seats`, `lay_curved`). 열별 좌석수는 실제와 무관하다.
  - 표본: A22 실제 약 198석(4–26열, 열당 7–11석), 모델 A블록 평균 약 162석.
  - 모델 합계(HANDOFF 기준): A 7,944 · B 8,565 · F 5,496 · C 2,016 · D 4,656 · E 8,356 · G 1,053.
- 높이는 블록(손가락)마다 앞·통로·뒤 세 앵커를 맞춰 선형으로 깐다(A 1.0 m + 0.17/열, B 5.5 m + 0.255/열). 앵커가 블록마다 따로 맞춰지면서(`fit_profiles_balanced`, `fit_straight`) 같은 열 번호라도 블록마다 높이가 달라지고, 폴 쪽에서는 위로 갈수록 기울기가 줄어든다.
- 생성기는 저장소의 입력만으로 다시 돌릴 수 있다.
  - `td_gen.py`, `td_rowsA.py`, `td_build.py`가 쓰는 입력은 `td/td_labeled.json`, `td/td_vec.json`이다.
  - 중간 파일 `td_stage1.pkl`, `td_rowsA.pkl`은 앞 단계가 만든다.
  - 이 PC에는 opencv, scipy, shapely가 설치되어 있지 않다.

## 3. 자료 만들기 (1단계)

kurumicat 좌석표 이미지 약 19장(1층 10, 외야 2, 익사이트 1, 2층 6)을 브라우저로 열어 읽고 `venue-lab/pipeline/td/td_rows_real.json`으로 옮긴다. 파일은 내려받지 않고 화면에서 읽는다.

```json
{ "A22": { "rows": { "4": [61, 67], "5": [61, 67], "26": [61, 71] } },
  "D15": { "rows": { "8": [221, 228] }, "terrace": { "8": [...] } } }
```

- 한 열에 번호가 끊기는 경우(통로, 스카이테라스 박스)는 구간 목록으로 적는다.
- 약 4천 개 열이라 옮기다 틀릴 수 있다. 다음 자동 검사로 걸러낸다.
  1. 블록의 열 범위와 첫 번호가 공식 `td_labeled.json`과 같은지
  2. 같은 블록 안에서 번호가 열마다 급하게 튀지 않는지
  3. 1루·3루 대칭 블록끼리 열별 좌석수가 같은지(다르면 이미지를 다시 확인)
- 출처와 "실제와 다를 수 있음"을 파일 머리와 HANDOFF에 적는다.

## 4. 생성기 바꾸기 (2–4단계)

### 2단계: 기준선 재현

- 필요한 패키지를 설치한다: opencv-python, scipy, shapely, scikit-image.
- 코드를 바꾸지 않은 채로 `td_gen.py` → `td_rowsA.py` → `td_build.py`를 돌린다. 결과가 커밋된 `td_stands.json`과 같은지 비교한다.
- 같지 않으면 원인부터 찾는다. 재현이 안 되면 이후 단계를 진행하지 않고 보고한다.

### 3단계: 높이와 단차 정리

- **높이는 층(A, B, F, D, E)마다 열 번호만으로 정한다.** 같은 열 번호는 어느 블록이든 같은 높이에 둔다. 통로를 사이에 둔 두 블록의 단이 맞물리고, 블록마다 앵커를 따로 맞추는 일이 없어진다.
- **기울기는 위로 갈수록 같거나 가팔라지게만 둔다(줄어들지 않게).** 1층 A는 앞이 완만하고 뒤로 갈수록 가팔라지는 건물 단면을 따른다.
- 블록이 콘코스(10.6 m)보다 낮은 열에서 끝나는 경우(폴 쪽 B 등)는 높이를 억지로 끌어올리지 않는다. 뒤쪽 계단이나 벽으로 콘코스와 잇는다. 이미 있는 `flights`, 착지면 장치를 쓴다.
- 외야 F는 펜스에서 세는 지금 방식을 유지하되, 열마다 높이가 고르게 늘게 한다.
- 폴 쪽 코너(K면)는 마지막에 손댄다. 둘레의 단 높이가 정해진 다음, 그 사이를 계단식으로 잇는다.

### 4단계: 열과 좌석 다시 깔기

- 각 블록의 열 수는 실제 열 범위대로 둔다. 실제에 없는 열은 단을 깔지 않는다(예: A22의 1–3열).
- 각 열은 실제 좌석수 × 좌석 폭(기본 0.5 m)만큼의 단을 깐다. 홈 쪽 통로에서 시작해 바깥쪽으로 채운다. 번호가 작은 쪽이 홈 쪽이고, 좌석표에서 바깥쪽 끝이 계단 모양으로 들쭉날쭉한 것도 그대로 따른다.
- 열 길이가 블록 외곽선을 넘거나 크게 모자라면 좌석 폭을 0.45–0.55 m 안에서 조정한다. 그래도 맞지 않는 열은 목록으로 보고한다.
- 블록 사이 통로 폭은 지금 값(약 1.2–1.3 m)을 유지하고, 통로 계단과 문은 새 단 위에 다시 놓는다.
- 스카이테라스(D 8–9열 일부)는 좌석 대신 테라스 박스 자리를 비워 둔다.
- 익사이트석 G는 실제 블록(10석 단위)대로 다시 깔고, 펜스를 G 좌석 앞선을 따라 매끈하게 다시 긋는다. 펜스가 좌석·단과 겹치거나 끊기는 곳이 없게 한다. 깨지는 지점은 2단계에서 앱 화면으로 먼저 찾는다.

## 5. 앱에 옮기기와 확인 (5단계)

- `python3 pipeline/mkdata.py td` → `venue-lab/src/j0-td-data.js`, 앱의 `src/three/venues/td-data.js`를 갱신한다. `dome.js`의 좌석 색·`seatKeep`·익사이트 박스 조건이 새 데이터와 맞는지 확인한다.
- 확인 항목:

| 항목 | 기준 |
| --- | --- |
| 좌석수 | 블록별 실제 대 모델 표. 차이 0이 목표, 남는 차이는 이유와 함께 표로 남긴다 |
| 단차 | 같은 열 번호의 높이가 블록 간 ±2 cm 이내, 열마다 기울기가 줄지 않음 |
| 외야 쪽 코너 | A01/A49, A02/B02, F20/F01 둘레를 여러 시점에서 렌더해 단이 뜨거나 파묻히거나 겹치지 않음 |
| 걸어서 닿기 | `reachcheck.py`로 모든 좌석에 걸어서 닿고, `vomtest.mjs`로 모든 출입구를 지나감 |
| 익사이트 펜스 | 펜스가 끊기거나 좌석·단을 뚫는 곳이 없음 |
| 응원봉 블록 | 돔 스탠드 블록 분리가 지금처럼 나옴(`aisleBlocks` 결과를 렌더해 비교) |
| 성능 | 좌석·관객 수가 늘어난 만큼 프레임 시간을 다른 공연장과 비교 |
| 좌석배치도 | `node scripts/venue-maps.mjs`로 돔 2장을 다시 만든다 |

- 단계마다 따로 커밋한다. 외야 쪽 코너에서 문제가 생기면 그 단계만 되돌릴 수 있게 한다.

## 7. 남은 결정

- 패키지 설치: 이 PC의 파이썬에 opencv-python, scipy, shapely, scikit-image를 설치해도 되는지.
- 좌석 폭: 실제 좌석 폭 자료가 없어 0.5 m를 기본으로 둔다. 좌석표와 외곽선이 크게 안 맞는 블록이 많으면 그때 다시 정한다.
- 열 높이 단면(A·B의 열별 높이): 지금 앵커값(A 1.0 m + 0.17/열, B 5.5 m + 0.255/열, 콘코스 10.6 m)을 기본으로 두고, 기울기가 줄지 않게만 고친다. 실제 단면 자료가 있으면 그것으로 바꾼다.
