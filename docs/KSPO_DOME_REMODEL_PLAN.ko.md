# KSPO DOME 전면 재작업 계획서

작성 기준: 2026-11-22. 대상 커밋 `a0f9c12` (Add KSPO DOME with General and 360 concert layouts). 대상 파일: `src/three/venues/gymnastic-*.js`, `src/three/gymnastic-arena-plan.js`, `venue-lab/pipeline/gymnastic_arena.py`, 그리고 KSPO DOME를 공용 공연 경로에 연결할 때 수정할 공용 파일들.

최초 구현은 좌석 좌표, 두 모드의 피커, 음향만 연결한 기본 작업이다. 이 계획은 Arena·Dome·Stadium과 같은 수준의 디테일을 목표로 한다. 범위는 보미토리, 콘코스, 내부 구조, 조명과 팬라이트, 무대, 텍스처, 펜스, General 밴드셋, 좌석 실측 검증, 전석 관객이다. 기존 [개발 계획](GYMNASTIC_ARENA_DEVELOPMENT_PLAN.ko.md)과 [자료 모음](references/GYMNASTIC_ARENA_REFERENCES.ko.md)의 출처와 좌표 기준은 그대로 사용한다.

## 3. 작업 계획

### 3.1 자료 확보와 좌석 실측 검증

1. **원본 다운로드.** 운영사 1–3층 PDF, 상세 EPS ZIP, 고해상도 좌석도 JPG, DAE ZIP(약 59MB)을 세션 작업 디렉터리에 받는다. SHA-256을 자료 모음 문서의 값과 대조하고, 원본은 커밋하지 않는다.
2. **파이프라인 재실행.** `gymnastic_arena.py`로 EPS와 DAE를 다시 읽는다. 구역별로 좌석 기호 개수, 열 라벨, 열별 좌석 수를 따로 뽑는다. 블록 단위로 복제된 좌석 수가 원본에서 온 것인지 생성 단계의 템플릿인지 먼저 판정한다.
3. **좌석 감사표.** 52개 구역마다 운영사 웹 수치, EPS 중앙 표, EPS 개별 라벨, DAE 인스턴스, 현재 추출값을 한 표에 둔다. 2F 초과분 267석의 원인(BOX, 접근성 위치, 기자석, 중복)을 구역 단위로 설명한다. 23·42·44·48·49, BOX 1–8, C 뒤 접근성 플랫폼은 필수로 검사한다.
4. **번호 체계.** 열 번호 방향과 좌석 번호의 진행 방향을 현장 사진의 좌석 스티커와 구역 표지로 맞춘다. 표본은 8구역 11열 5·6번, 2구역 2·12·15·20열, 26구역 1·13열, 27구역 4열 14번, 28구역 1열 14번, 36구역 8열 10번, 42구역 1·4·5·7열이다. 근거가 없는 번호는 계속 `estimated`로 두고 감사표에 남긴다.
5. **시점 대조.** 위 표본 좌석에서 앱 시점을 렌더해 사진과 나란히 비교한다(`rxshot.mjs`, `compare.py`). 난간, 앞 열, 통로, 무대 방향이 맞아야 한다.
6. **생성물 갱신.** `gymnastic-data.js`를 다시 생성하고 블록맵(`gymBlockMap`)과 피커를 확인한다. 좌석 수가 바뀌면 `src/data.js`의 표시 수치와 음향의 관객 면적도 갱신한다.

### 3.2 보미토리

- DAE와 2·3층 PDF에서 보미토리의 위치, 폭, 깊이, 잘린 열, 머리 높이를 뽑아 `GYM_VOMS` 데이터로 만든다. 좌석 데이터에서 열이 끊기는 지점과 대조한다.
- 2F 스탠드의 보미토리는 흰 박스 머리(상부 마감), 측벽 파라펫, 바닥 경사·계단, 개구부 안쪽 벽으로 구성한다. 공용 `vomParts`의 벽·캡·터널 형상을 원형 좌표에 맞게 감싸 쓴다.
- 1F 하부는 중간 통로로 들어오는 2F 콘코스 출입구와 플로어 GATE 1-1/1-2/1-3 터널을 만든다.
- 각 보미토리에 구역 안내 표지(예: `27구역 28← →26`)를 `vomSignTexture`/`signSheet`로 붙이고, 입구 조명과 콘코스 쪽으로 이어지는 통로 조명을 둔다.
- 상부 스탠드의 통로 계단을 별도 메시로 만든다. 디딤판, 노란 논슬립 띠, 중앙 손잡이를 넣고, 보행 충돌 메시는 같은 외곽선에서 생성한다.

### 3.3 콘코스(2F·3F 전체 링)

- 2F 콘코스는 하부 스탠드 뒤, 3F 콘코스는 상부 스탠드 뒤에 360° 연속으로 만든다. 폭과 층고는 2·3층 PDF에서 읽는다.
- 바닥, 천장과 다운라이트, 벽 마감, 기둥, 매점·화장실 출입문 표면, 게이트·구역 방향 사인을 둔다.
- 2F↔3F 계단 코어와 관객 게이트 2-1/2-2/2-3을 도면 위치에 맞춰 연결한다. 외부 광장과 외벽은 범위 밖이다.
- 콘코스 조명은 공연 조명과 따로 상시 점등한다. 객석에서 보미토리를 통해 밝은 콘코스가 보이게 한다.
- `walk.js` 보행 경로를 연결한다. 게이트에서 콘코스, 보미토리, 통로, 좌석까지 이어져야 한다. Tokyo Dome 재작업의 다층 콘코스·계단 연결 방식을 재사용한다.

### 3.4 내부 구조

- **지붕 트러스.** 방사형 주 트러스(상·하현과 사재가 있는 래티스), 링 트러스, 캣워크와 난간, 중앙 링과 매단 하우스 스피커 클러스터를 만든다. 인스턴스 메시로 부재 수를 감당한다. 트러스 사이에는 흰 흡음 배플을 경사지게 단다. 부재 간격과 단 수는 2018 실내 전경과 DAE에서 맞춘다.
- **상부 벽 띠.** 밝은 회색 패널, 작은 사각 창, 벽부등, 방송·조명 부스 창을 만든다. BOX 1–8에는 유리 전면과 내부 조명을 둔다.
- **1F 하부.** 접힌 가동석 앞면을 유닛 단위로 분절하고 좌석 등받이가 접힌 모양을 표현한다. 1F 고정석 앞 파라펫, 중간 통로, 열 끝 계단, C 뒤 접근성 플랫폼을 정비한다.
- **플로어 레벨.** 아레나 외곽 벽, 게이트 1-1/1-2/1-3 개구부, A 쪽 장비 반입구를 만든다.
- 시설 레이어와 공연 레이어를 분리해, house/show를 비교할 때 시설과 장비가 구분되게 한다.

### 3.6 공연 경로 이전

- `CONCERT_VENUES`에 KSPO DOME를 추가해 공용 GLB 장비를 로드한다. 기타·베이스는 `theater-backline.glb`에 있으므로 KSPO에서 함께 로드하거나 공용 GLB로 옮긴다.
- `stage-plan.js`의 `CONCERT_LAYOUTS`에 KSPO의 General·360을 등록한다. `concertProduction`의 arena/dome/stadium 분기에 KSPO 분기를 추가하거나, 베뉴별 설정 객체로 분리한다.
- `data/concert-equipment.json`에 `gymnastic-arena-general`과 `gymnastic-arena-360` 항목(펜스, 무대 소품, 플로어 소품, 카메라, 지브, 서브, 필, 바닥 조명)을 추가한다.
- 기존 `gymnastic-show.js`의 원시 도형 무대·장비는 이전이 끝나면 제거한다.

### 3.7 무대

**General: T자 돌출**

- A 블록 쪽 엔드 스테이지, 대형 백스크린, 좌우 IMAG, 트러스 행어를 둔다.
- 중앙 런웨이를 내고, 끝에서 좌우로 가로 돌출부를 낸다. 돌출 길이와 폭은 RIIZE 공식 배치도를 기준으로, 착석 플로어 폭과 통로를 확보하도록 정한다.
- 데크 가장자리 LED 스트립, 데크 아래 스커트, 계단과 난간, 좌우 윙과 마스킹을 둔다.
- 착석 플로어 블록은 T자 돌출 양옆과 앞쪽으로 다시 나누고, 2D 피커 실루엣을 같은 평면에서 생성한다.

**General 밴드셋(중앙 업스테이지, 5인)**

| 파트 | 구성 |
|---|---|
| 드럼 | 중앙 업스테이지 드럼 라이저(계단과 난간), 드럼 키트 |
| 베이스 | 베이스, 스탠드, 앰프 |
| 기타 2 | 기타, 페달보드, 앰프 2조(좌우) |
| 키보드 | 키보드 스탠드, 키보드 |
| 공통 | 웨지, DI, 투어링 랙, 플라이트 케이스, 신호 코일, 케이블 가드, 접촉 그림자 |

악기와 앰프는 연주자가 객석을 향하도록 배치하고, 업스테이지 라이저는 백스크린 하단과 겹치지 않게 높이를 정한다. 보컬 마이크는 런웨이와 메인 데크 앞쪽에 둔다.

**360°: DAY6 2025년 5월 피날레**

- 낮은 원형 데크의 흰 측면 마감과 로고 띠, 중앙의 높은 원형 드럼 라이저, 투명 차음 패널을 만든다.
- 밴드는 GLB 장비로 교체한다. 기타, 베이스, 키보드, 마이크, 웨지, 페달보드의 위치는 JYP 무대 사진과 공식 영상 각도로 맞춘다.
- 중앙에 매단 검은 격자 트러스, 여러 방향의 상·하단 IMAG, 가장자리 PA를 공용 경로로 다시 만든다.
- 19구역 콘솔(FOH), S1–S6 스탠딩 구역, 계단 위치를 유지한다.

### 3.8 펜스

| 종류 | 내용 |
|---|---|
| 무대 앞 바리케이드 | 공용 GLB `barrier`를 메인 데크, 런웨이, T자 돌출 앞에 두르고 보안 피트 폭을 확보한다. 360은 원형 데크 둘레에 두른다. |
| 플로어 블록 펜스 | 착석 블록 사이에 철제 이동식 펜스를 두고 흰 가림막 패널을 붙인다. 통로에는 게이트를 둔다. |
| 시설 난간 | 1F 중간 통로의 이중 난간과 구역 번호판, 2F 전면 난간과 구역 방향 표지, 계단 손잡이, BOX 앞 유리, 보미토리 파라펫, 접근성 플랫폼 난간을 만든다. |
| 360° 스탠딩 펜스 | S1–S6 사이의 방사형 통로 펜스, 무대 쪽 내측 링, 스탠드 쪽 외측 링, 출입 게이트를 만든다. |

모든 펜스에 보행 충돌 메시를 붙이고, 관객 배치에서 제외 영역(floor exclusion)으로 등록한다.

### 3.9 조명

- **하우스 조명.** 지붕 트러스 노드에 하이베이 픽스처를 모델링한다. 하우스 조명을 켜면 2018 실내 전경처럼 밝은 백색 볼이 되게 한다. 콘코스와 보미토리 조명은 상시 점등한다.
- **공연 조명.** 공용 경로의 트러스 행(wash/beam/spot/par), 픽스처 바디, 데크 LED, 블라인더, 스트로브, 바닥 조명, 업라이트를 General T자 무대와 360 원형 트러스에 맞춰 배치한다. 팔로우 스폿은 상부 후면 부스 위치에 둔다.
- **rx 설정.** `rx/index.js`의 `LOOK`에 KSPO DOME 두 모드(헤이즈, 노출, `fogFar`, 프로브 위치)를 추가한다. 구조가 확정되면 `bake-gi.mjs`로 `gymnastic-arena-general.gi`와 `-360.gi`를 굽는다.

### 3.10 팬라이트와 전석 관객

- **전석 관객.** 각 모드에서 열린 좌석 전부를 관객으로 채운다(현재는 약 50%). General의 무대 뒤 가림막에 막힌 닫힌 좌석은 실제 공연처럼 비워 둔다. 착석 플로어와 360 스탠딩 구역도 같은 밀도로 채운다. 품질 설정 `low`에서는 관객 디테일만 낮추고 좌석 점유는 유지한다.
- **광점.** 사진과 비교해 응원봉 광점의 크기, 최대 픽셀, 밝기, 켜진 비율을 KSPO 거리에 맞게 조정한다.
- **구역 연출.** General은 착석 블록, 1F 구역 1–22, 2F 구역 23–52를, 360은 S1–S6와 객석 방위를 연출 구역으로 매핑한다. `splitTurn`과 구역 경계를 정의해 섹션별 색, 파도, 그라데이션이 구역 단위로 맞게 한다. `useCrowdLight`의 UI와 동작을 함께 확인한다.

### 3.11 음향과 앱 연동

- 무대 위치와 PA 배열이 바뀌므로 `GYM_PA`, `GYM_FOH`, `venuerooms.js`의 PA·FOH 좌표와 관객 면적을 갱신하고 `npm run verify`를 실행한다.
- 착석 플로어 블록과 좌석 수가 바뀐 뒤 피커, 저장·복원, 모드 전환 시 좌석 무효화를 다시 검증한다.
- `scripts/venue-maps.mjs`로 General·360 썸네일을 다시 생성한다.

## 5. 검수 기준

- **좌석 데이터.** 52개 구역의 좌석 수와 원본별 수치 차이가 감사표로 설명된다. 3.1의 표본 좌석에서 렌더한 시점이 사진의 난간, 앞 열, 통로, 무대 방향과 맞는다. 피커의 구역–열–번호와 3D 좌석이 일대일로 대응한다.
- **비교 시점.** 2018 실내 전경과 같은 구도(하우스 조명, 공연 장비 숨김), 2025 1F 시점, 2F 27구역 4열, DAY6 스탠딩 앞 펜스, 1F 8구역에서 실물 사진과 나란히 비교한다.
- **보행.** 게이트에서 콘코스, 보미토리, 통로를 거쳐 좌석까지 이동한다. 콘코스를 한 바퀴 돌고 2F↔3F를 오간다. 난간·펜스·장비를 관통하거나, 계단에서 떨어지거나, 보이지 않는 벽에 막히지 않는다(`vomtest.mjs`, `reachtest.mjs`, `rowwalk.mjs`, `walkshots.mjs`).
- **공연.** General T자 돌출 양옆의 시야와 무대 뒤 가림, 밴드 배치, 360의 전방위 IMAG와 S1–S6를 확인한다. 재생 중 모드나 베뉴를 바꿔도 이전 모드의 좌석, 광원, 오디오가 남지 않는다.
- **팬라이트.** 전석 점유 상태에서 구역 연출 패턴이 블록·구역 경계와 맞는다.
- **성능.** 같은 뷰에서 Arena와 프레임 시간, 진입 시간, 메모리를 비교한다. 모드 왕복 10회 후 GPU 메모리와 장면 객체 수가 계속 늘지 않는다. `low` 품질에서도 구조와 좌석 선택은 동일하다.
- **빌드.** `npm run build`, `npm run verify`, `node venue-lab/build.mjs`, `uitest.mjs`, `apppick.mjs`를 통과하고, 기존 6개 베뉴가 회귀하지 않는다.
