# Song2Concert

내 음원을 **실제 공연장에서 듣는 것처럼** 들려주는 웹 앱입니다.
FLAC/WAV 파일을 올리면, 다섯 곳의 공연장 중 한 곳을 골라 그 공간의
잔향(reverb)으로 재렌더링해 들려줍니다. 화면은 1인칭 관객 시점의 공연장
장면(SVG)으로 가득 채워지고, 그 위에 오디오파일 콘솔 스타일의 정보 패널이
얹힙니다. 핵심은 **실제 Web Audio API 컨볼루션 리버브 엔진**으로 동작한다는
점입니다 — 가짜 효과음이 아니라 공연장별 임펄스 응답(IR)을 합성해 음원에
컨볼루션을 겁니다.

## 실행 방법

```bash
npm install
npm run dev      # → http://localhost:5173
npm run build    # dist/ 에 프로덕션 빌드
npm run preview  # 빌드 결과 미리보기
```

브라우저에서 열고, 화면 가운데의 **"Drop a FLAC / WAV to begin"** 버튼이나
상단 **File** 메뉴로 음원을 올린 뒤 재생하면 됩니다. (Chrome / Edge / Firefox /
Safari 동작 확인)

## 여섯 공연장

각 공연장은 **잔향 설정값이 아니라 실제 형상**으로 기술됩니다 — 치수, 표면 재질,
무대와 좌석의 위치. 아래 표의 RT60·베이스비는 거기서 계산되어 나온 값이지 적어
넣은 값이 아닙니다 (`npm run verify:acoustics`로 검증).

청취 위치는 각 공연장의 **이상적인 좌석**입니다. 클럽·극장·콘서트홀은 평론가가
찾아가는 자리, 아레나·돔·스타디움은 **FOH(콘솔) 위치** — 타협이 아니라 공연이
실제로 그 지점에서 제대로 들리도록 믹스되는 자리입니다.

| 공연장 | 규모 | 부피 | RT60 | 베이스비 | 첫 반사 | 측면 반사 |
| --- | --- | --- | --- | --- | --- | --- |
| Club | 300석 | 672 m³ | 0.75 s | 0.85 | +6 ms | 0.14 |
| Theater | 3,000석 | 15,000 m³ | 1.28 s | 1.01 | +16 ms | 0.39 |
| **Concert Hall** (빈야드) | 2,000석 | 22,000 m³ | 2.02 s | 1.20 | +12 ms | 0.31 |
| Arena | 22,500석 | 400,000 m³ | 2.64 s | 1.14 | +44 ms | 0.00 |
| Dome | 45,000석 | 1,240,000 m³ | 3.63 s | 1.50 | +84 ms | 0.00 |
| Stadium | 90,000석 | 1,139,100 m³ | 2.15 s | 1.18 | +112 ms | 0.00 |

**베이스비**(RT60@125Hz ÷ 중역)가 핵심입니다. 좋은 콘서트홀은 1을 넘습니다 —
저역이 중역보다 오래 울리고, 그게 홀이 "따뜻하다"는 말의 정체입니다. 흡음의
대부분을 담당하는 관객이 125Hz에서는 1kHz의 절반도 흡수하지 못하기 때문에
물리적으로 그렇게 됩니다. 반대로 우드 패널 클럽은 1보다 작고, 경량 골조에
두꺼운 업홀스터리를 쓴 극장은 1.01로 거의 평탄합니다. 어느 쪽도 설정한 값이
아니라 재질에서 나온 결과입니다.

**Concert Hall은 빈야드 형식**입니다 — 중앙 무대를 둘러싸고 객석이 테라스로
계단을 이룹니다. 이 형식이 통하는 이유는 각 블록이 자기 낮은 벽으로 둘려 있어
**모든 좌석이 몇 미터 옆의 면에서 측면 반사를 받는다**는 점입니다. 슈박스는
20m 떨어진 옆벽에서, 그것도 1층에서만 받습니다. 그래서 첫 반사가 +12ms로 가장
이르고(친밀함), 측면 반사 비율은 0.31입니다.

대형 3개의 형상은 각각 사이타마 슈퍼 아레나(아레나 모드) · 도쿄 돔 · 웸블리
스타디움에서 가져왔습니다. 도쿄 돔의 124만 m³와 웸블리의 1,139,100 m³는 공표된
수치이고, 아레나는 수용 인원과 건물 규모에서 추정한 값입니다.

## 주요 기능

- **공연장 잔향 재현** — 공연장의 형상에서 임펄스 응답을 합성해 컨볼루션합니다.
  초기 반사는 이미지 소스법으로 하나씩 계산되고(물리적 지연 · 1/r 감쇠 ·
  표면별 흡음 · 도달 방향), 후기 잔향은 옥타브마다 각자의 속도로 감쇠합니다.
- **트루 스테레오 컨볼루션** — 4채널 임펄스. 믹스의 좌/우가 각각 좌/우 음원
  위치의 룸 응답을 거칩니다.
- **거리 컨트롤** — 웻 슬라이더는 각 공연장의 **물리적으로 올바른 잔향 레벨**을
  중심으로 ±12dB 트림합니다. 직접음 레벨은 움직이지 않습니다 — 잔향이
  많아진다고 방이 직접음을 줄이지는 않으니까요.
- **라우드니스 보상** — 공연장 100dB SPL을 헤드폰 75dB로 들을 때 빠지는 저역을
  등청감 곡선 형태로 되살립니다.
- **트랜지언트 셰이핑** — 킥·스네어의 어택만 강조합니다. 정적 EQ와 달리 같은
  대역의 베이스 기타·보컬 치찰음·심벌은 건드리지 않습니다.
- **보컬 앵커** — 이 곡의 보컬이 프로그램 대비 평소 차지하는 비율을 학습해,
  구간이 바뀌어도 보컬 레벨이 일정하게 유지되도록 합니다.
- **룩어헤드 리미터** — 스레숄드 아래에서 게인 변화 0.00dB. 안전망이지
  톤 컨트롤이 아닙니다.
- **주파수 의존 음원 지향성** — 잔향장에 들어가는 고역이 직접음보다 적습니다.
  실제 목소리·라인 어레이가 그렇고, 보컬 명료도를 좌우합니다.
- **잔향이 즉시 시작** — 방이 산란으로 되돌려 보내는 순간부터. 첫 정반사 시각에
  묶어두면 EDM 인트로에서 킥 잔향이 엇박 딜레이처럼 들립니다.
- **방이 우는 만큼 서브를 조향** — 저역 잔향 시간에 비례해 잔향 센드의 저역을
  깎습니다. 도쿄 돔 −10dB, 스타디움 −6.5dB. 직접음은 안 건드리므로 양감·타격감은
  그대로입니다.
- **크로스피드** — 700Hz 아래 하드팬 성분(실제 머리가 만들 수 없는 단서)을
  정리해 이어폰에서 소리가 머리 안에 갇히는 현상을 완화합니다. 미드/사이드의
  사이드에만 걸어 중앙은 수학적으로 그대로입니다.
- **재생 큐 · 볼륨 · 탐색 · 앨범 아트 펄스 · 메타데이터 자동 추출**
- **FLAC 내보내기** — 재생과 **완전히 동일한 그래프**로 오프라인 렌더링합니다
  (같은 코드, 두 번 호출). 원본의 비트 심도(16/24bit)와 샘플레이트를 보존하며,
  볼륨 노브는 모니터링 컨트롤이므로 파일에 구워 넣지 않습니다.

## 동작 원리

### 오디오 그래프 (`src/audio/engine.js`)

```
                                      ┌─► (드라이 EQ) ─► [거리 감쇠] ─► [M/S 폭] ─► [dryGain] ──────┐
  <audio>/buffer ─► [서브소닉 컷] ─► in ┤                                                            ├─► [mixBus]
                                      └─► [preDelay] ─► [convolver] ─► (웻 EQ) ─► [wetGain] ─► [ducker] ─┘
  [mixBus] ─► [글루 컴프] ─► [PA 새추레이션] ─► [master] ─► [limiter] ─► 출력
                                                  └─► [analyser] (펄스용 RMS)
```

- **소스** — 업로드 파일은 기본적으로 숨겨진 `<audio>` 엘리먼트로
  스트리밍됩니다(`createMediaElementSource`). 단, FLAC·WAV·AIFF 같은 무손실
  파일은 브라우저 `<audio>` 디코더가 못 다루는 경우가 많아(특히 Chrome/Edge의
  고음질 FLAC), `decodeAudioData` → 실패 시 **WASM FLAC 디코더**로 폴백해
  `AudioBufferSourceNode`로 재생합니다.
- **드라이/웻** — `dryGain`(원음)과 `wetGain`(잔향)을 등전력 크로스페이드로
  섞습니다. `preDelay`(DelayNode)는 청취 위치의 첫 반사음 도달 시간을, 포화
  곡선으로 압축해 타격음과 잔향이 분리(메아리)되지 않게 모델링합니다.
- **드라이 음색(콘서트 PA 보이싱)** — 직접음에만 거는 EQ로 라이브 PA의 토대를
  만듭니다: 서브 양감(로우셸프 ~120 Hz) + 킥 펀치(~60 Hz)/베이스 바디(~110 Hz)
  주파수 분리, 보컬 프레즌스(~2.8 kHz), 스네어 크랙(~4.5 kHz). 대형 공연장은
  직접음 스테레오 폭을 살짝 좁히는 M/S 매트릭스(`dryWidth`)로 PA의 모노 성향을
  반영하되 악기 분리감(또렷함)은 유지합니다.
- **웻 경로 EQ** — 잔향에만 적용되는 4단 EQ로 잔향이 리듬·보컬을 덮지 않게
  합니다: 로우컷(~170 Hz HP — 킥·베이스 바디는 직접음에 유지) · 머드 컷(~300 Hz) ·
  보컬/스네어 컷(~3.6 kHz) · 에어 컷(6 kHz 하이셸프). 실제 라이브 음향
  엔지니어가 잔향을 다듬는 방식과 같습니다.
- **웻 더커** — `AudioWorklet` 사이드체인(`public/wet-ducker-processor.js`)이
  드라이 엔벨로프를 따라가, 드럼만 나오는 스파스 구간에서 노출되는 잔향 꼬리를
  눌러 어색한 울림을 막습니다.
- **PA/거리 캐릭터** (`data.js`의 공연장별 `pa` 블록) — ① **거리 감쇠**: 청취
  거리에 따른 공기 흡음을 하이셸프 컷(9 kHz, 클럽 −0.5 dB → 스타디움
  −4 dB)으로 반영해 "무대에서 멀다"는 가장 강한 톤 단서를 만듭니다. 보컬
  자음·스네어 크랙 대역(~2.8/4.5 kHz)은 건드리지 않습니다. ② **글루
  컴프레션**: FOH 마스터 버스처럼 아주 완만한 컴프레션(3:1 미만, 느린 어택으로
  타격감은 통과)으로 믹스를 살짝 응집시킵니다. ③ **PA 새추레이션**: tanh
  소프트 새추레이션으로 대음량 PA의 하모닉 밀도를 더합니다(자연 음향 홀은
  바이패스). ④ **서브소닉 컷**: 실제 PA가 재생 못 하는 ~30 Hz 미만을
  정리합니다. ⑤ **밴드 분할 시스템 프로세싱**: 실제 PA 시스템 프로세서처럼
  200 Hz 크로스오버(LR4)로 저역을 갈라 전용 컴프레서로 레벨링하고,
  새추레이션은 그 위 대역에만 걸어 부스트된 저역이 믹스를 왜곡시키지 않게
  합니다.
- **리미터** — 마지막 단의 `DynamicsCompressor`가 어떤 공연장/믹스/입력
  레벨에서도 클리핑이 나지 않도록 안전망 역할을 합니다.
- **펄스** — `AnalyserNode`가 마스터 버스의 RMS를 매 프레임 읽어 앨범 아트
  맥동을 구동합니다.

### 임펄스 응답 합성 (`src/audio/impulse.js`)

공연장별 음향 파라미터(`src/data.js`의 `ir` 블록)로부터 스테레오 IR을 직접
합성합니다. 라이브 음향 실무를 따라 설계되었습니다:

- 시간에 따라 차단 주파수가 내려가는 로우패스로 **고역이 먼저 사라지는** 자연
  스러운 감쇠를 만듭니다.
- **저역 잔향을 짧게** 유지해(`lfDamp`) 베이스가 부밍하지 않고 타이트하게
  들리도록 합니다. 펀치감은 드라이 경로가 담당합니다.
- **측면 초기반사**(`lateral`) — 좌우에서 도착하는 반사음을 양귀 시간차(~0.5 ms)로
  배치해 콘서트홀 특유의 "감싸오는" 공간감(envelopment)을 만듭니다. 콘서트홀이
  가장 강하고, 친밀한 클럽은 약합니다.
- **딜레이 타워**(대형 공연장, `slap`) — 개별 메아리(슬랩백) 대신 시간 정렬된
  타워처럼 확산된 반사 클러스터로 거대 공간의 양감만 더합니다.
- 다이렉트 → 초기 반사 → 후기 잔향 구조, 코사인 페이드아웃(절단 클릭 방지),
  L2 에너지 정규화로 공연장마다 일정하고 안전한 웻 레벨을 유지합니다.

실제 제품이라면 이 합성 IR을 측정된 실측 IR로 교체하면 됩니다.

```
  verify-acoustics.mjs       룸 모델 측정 → 명공연장 기준값과 대조
  verify-ir.mjs              합성된 임펄스 측정 → 룸 모델의 주장과 대조
  audio-smoke.mjs            실제 브라우저에서 전 공연장 렌더 (Playwright)
```

## 검증

임펄스를 합성해서 쓰기 때문에 A/B할 실측 응답이 없습니다. 그래서 귀로 상수를
돌리는 대신 **측정**합니다.

```bash
npm run verify            # 아래 셋 모두
npm run verify:acoustics  # 룸 모델: RT60 · 베이스비 · 첫 반사 · 측면 반사 비율
npm run verify:ir         # 합성 결과: RT60 · C80 · EDT · 양귀 상관도
npm run verify:audio      # 브라우저 실렌더: 워크릿 · 4채널 컨볼루션 · 피크
```

이 스크립트들이 실제로 잡아낸 것들:

- **리미터가 스레숄드 아래에서 동작하고 있었습니다.** Web Audio
  `DynamicsCompressor`를 리미터로 쓰고 있었는데, 스레숄드보다 **34dB 낮은**
  임펄스에 **11.6dB의 게인 리덕션**을 걸었습니다. 타격음마다 전체를 눌렀다가
  뒤의 잔향으로 풀려서, 보컬 대역 명료도(C50)가 −2.1dB에서 −12.3dB로
  떨어졌습니다. 룩어헤드 리미터(`public/limiter-processor.js`)로 교체.
- **공연장 전환 때마다 그래프 전체를 재구성**하고 있었습니다. 소스가 잠깐
  끊기고, 잔향 꼬리가 잘리고, 남은 그래프가 완전히 끊기지 않아 워크릿이 계속
  돌았습니다 — 전환마다 5개씩 누적됐습니다.
- **잔향 센드를 입력단에서 뽑고 있었습니다.** 트랜지언트 강조와 보컬 앵커가
  직접음에만 존재하고 잔향에는 없어서, 보컬이 밴드와 다른 공간에 있는 것처럼
  들렸습니다.

- 관객석 위를 스치는 반사를 거울처럼 처리해 반대편 스탠드에서 **-4dB 슬랩**이
  돌아오던 문제 (스치는 각도의 산란 누락).
- **음원 지향성 누락** — 라인 어레이가 뒤를 20dB 죽인다는 사실을 빠뜨려,
  웸블리에서 무대 뒤 구조물이 -4.7dB로 되받아쳤습니다.
- **저역 대역이 중역을 끌고 가던 합성 버그** — 밴드 분할이 1극이라 177Hz
  로우패스가 500Hz에서 9dB밖에 안 떨어졌고, 그래서 125Hz의 감쇠 속도가 중역까지
  끌고 갔습니다. 도쿄 돔에서 중역 RT60이 모델값 3.6초 대신 4.9초로 합성됐습니다.
- 잔향 에너지 계산이 언더플로해 스타디움 명료도가 **+63dB**로 나오던 버그.
- 130만 m³ 돔의 RT60을 3.4초로 적어둔 물리적 불가능.

## 기술 스택

React 18 · Vite 6 · Tailwind CSS 3 · Web Audio API · `@wasm-audio-decoders/flac` (디코딩) · `libflacjs` (FLAC 인코딩)

## 참고

- 음원은 **모두 브라우저 안에서** 처리됩니다. 서버로 업로드되지 않습니다.
- 데모용 샘플 음원은 포함되어 있지 않습니다. 직접 FLAC/WAV 파일을 올려야
  잔향과 내보내기를 사용할 수 있습니다.
